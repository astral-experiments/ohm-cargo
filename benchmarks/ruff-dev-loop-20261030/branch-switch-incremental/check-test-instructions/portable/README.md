# Rust compiler instructions on returning to Ruff PR 28335

This supplement compares Rust `7e71d315` and the branch-aware compiler `6b7f424e` with the same Cargo `2d44bd4a`, unchanged stock Wild and matched standard library. Each verb used two independent paired installations, one in each compiler order. Every installation started with new target and build directories, a fresh source checkout at the same visible path, and a verified locked offline registry. After ordinary builds on A and B, the first returns to A and B were counted. An unchanged B and two ordinary native returns followed. The eight installations ran sequentially on the same four H9 cores.

* `cargo +ohm check -p ruff_python_parser --locked --offline -j4 --message-format=json` compiled the parser and AST metadata. Consuming both outputs gave 64-byte `Expr` on A and 56-byte `Expr` on B. Requiring the opposite width produced the expected E0308. Both crates’ public hashes agreed between the profiled and ordinary returns. All raw metadata hashes remain in the ledger.
* `cargo +ohm test -p ruff_python_parser --lib --no-run --locked --offline -j4 --message-format=json` executed one stock Wild link per return. Each complete Linux executable matched the independently empty build of the same Ruff revision, listed exactly 245 tests and passed three selected parser/lexer tests. Cargo check returns executed zero linkers.

`instruction-counts.tsv` contains every paired, per-crate dynamic instruction count and their sums. P/Q is the parent compiler's guest Ir divided by the guarded compiler's Ir. These are descriptive counts for two pairs per verb. They do not estimate a population speedup or measure end-user elapsed time.

The controller left Cargo and rustup native. It identified each real compiler by inode and redirected its initial ELF loader call, preserving argument, environment and inherited jobserver descriptors. Each terminal count was verified three ways from the reported Ir total, Valgrind's terminal line, and the sum of all non-call-edge self costs. Native Wild ran outside Callgrind. Any extra direct fork from the parser with a header-only Valgrind log has an explicit PID record in the ledger, with zero events or collected totals. Per-process files, original argv and unmodified streams are retained in the separate raw archive committed by `verified.json`.

Two setup attempts are retained separately. The initial test gate compared dirty returns with an independently cold list of 151 Cargo artifacts. Both uninstrumented reference arms showed the correct dirty list has 149, omitting `unicode_width` and `annotate_snippets`. This attempt ended before either test compiler was instrumented. The subsequent attempt built and ran the correct test on return A, but the old build-only parser refused its extra fork-startup log. The final collector requires the original Rust kernel PID and rejects any extra instruction-bearing file. The incomplete test installation contributes no paired observation. The two already completed first-pair check installations were carried forward with a complete per-path integrity record; the remaining intervals used fresh states in their original preselected order.

Run `python3 -IB verify.py` to check the compact projection and reproduce the table. Full process-level profile, source, ELF, and syscall verification was completed independently from the retained raw files before this projection was sealed.
