Normal Ohm defaults consult the readiness marker before planning the reuse. One qualifying non-check build writes the marker on success. An explicit unstable flag or an already-ready shared registry directory can also satisfy this gate. None of the check-only resolver commands specified the flag or a shared registry. A marker indicates eligibility for planning, without proving any particular unit was substituted. [Release Cargo compile entry point](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/ops/cargo_compile/mod.rs#L429-L443), [readiness eligibility](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/ops/cargo_compile/mod.rs#L714-L740), [marker publication](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/compiler/mod.rs#L1947-L1957).

On an eligible check, the global rustc wrapper excludes two paths. `native_test_check_candidate` cannot substitute native build/test units for matching checked workspace targets. `can_reuse_built_registry_dependency` cannot promote eligible checked remote-registry or workspace library units to previously built artifacts. A workspace-only wrapper excludes the first path but allows externally owned registry dependencies in the second. Relevant additional eligibility includes compiler identity, logging, loader environment, target kind and build profile. The two specific graphs start from `UserIntent::Check` / `CompileMode::Check`. Plain build and test compilation select `Build` for their normal dependencies, so these particular guards do not explain changed build/test work. The historical role-counting runs still used a global wrapper on those endpoints. [Native candidate](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/compiler/unit_dependencies.rs#L1152-L1204), [dependency eligibility and loader/identity checks](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/compiler/unit_dependencies.rs#L1233-L1337), [dependency mode](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/compiler/unit_dependencies.rs#L911-L925).

Cargo includes the effective rustc and optional wrapper identities in its rustc-info fingerprint. Both compiler fingerprints and exact target cache mtimes are corroboration for the inherited warm-driver environment. The native resolver traces and distributed role-study traces provide direct per-process evidence for the corresponding modes. `LD_LIBRARY_PATH` from a counter launcher, by itself, is outside Cargo’s deny list. `LD_PRELOAD`, `LD_AUDIT` and the listed DYLD variables are inside it. An interposer that injects one after launch can change eligibility on marker-bearing targets. A stock executable printed environment and an actual reuse-sensitive Cargo build-then-check workload are required to certify any new externally observed ordinary check-after-build role count.
