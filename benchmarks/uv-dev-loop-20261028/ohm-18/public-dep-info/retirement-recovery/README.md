# PGO control retirement recovery

The Ohm Cargo -18 public dep-info study built and independently audited its #269 control. The next maintenance process exited 1 before deleting anything. Linux denied access to a one-thread zombie's descriptor directory. The original build, audit, failed return and generated-directory identities are preserved. The independent audit recorded Cargo SHA-256 `9a4327124d6ea1397895abb22b2d5373355909332e16d755d9979ae948a37b70` and merged profile SHA-256 `8c8d93298d5dfe5c5b03d6aed0f0b4162b6be9d430f2da53f36e55345ecb4acc` from 24 non-uv training commands.

The prospective replacement applies only to target retirement. A guest dry run verified the three original target inodes and inspected 20 live same-user process groups. Both unreadable groups were twice-confirmed single-thread zombies. A live reader, a protected live group or a zombie leader with a living sibling still stops cleanup. The recovery issues each later grant separately and reuses the successful control build and audit. The v3 schedule retains 17,664 native commands, 192 counted commands and all six required comparisons. This packet contains no measured command result from this study. ## Verify after extraction

Run the following on Linux with Python 3.11 or newer. Both commands work offline. The verifier checks recovery source hashes, the original 0/0/1 supervisor chain, raw failure, source/PGO identity, schedule, physical-bank assignments and 39 synthetic controls. The optional argument also verifies a separately downloaded copy of the previously published v3 package.

```sh
unzip maintenance-recovery.zip -d maintenance-recovery
cd maintenance-recovery
python3 -I -B verify.py
python3 -I -B verify.py --published-v3 /path/to/complete-command-registration-v3.zip
```
