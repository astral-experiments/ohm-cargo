# Independently trained Cargo PGO intermediates

The five exact adjacent Cargo PR heads are built in the published order `unit`, `warnings`, `feature`, `depfile`, `semver`. The unmodified standard-library sources, released Ohm compiler, `ohm-defaults,all-static`, ThinLTO, one CGU, and fixed source/target/profile locations match the original baseline PGO experiment. Every stage gets an empty target directory. The source/date stamp used for Cargo's self-reported version is fixed to the release in all arms. The individual commit and Git tree in `ready.json` identify the measured patch stage.

Each head executes 24 training operations independent of uv on the release's pinned bitmaps and Diesel fixtures. Both fixtures use check/debug/optimized modes, cold non-incremental, cold incremental, warm, and upstream patched incremental scenarios. The training sources, dependency seed, target/compiler settings and source-edited crate bytes match. The invoked instrumented executable lives in each arm's separate record directory. Each fresh profile is merged with the same verified LLVM 23.1.1 utility and supplied to all target Rust units in Cargo's component graph, leaving the host and std graphs on the original flags. The 315 target Rust units are recompiled for profile use. Native vendored libraries are rebuilt as part of each clean target.

Run `work/pgo-holdout/start-intermediates.sh` only after the endpoint audit has finished and before starting any other consumer of the stable build paths. The executable checks both existing endpoint hashes, the pristine std path source, the frozen PR commit/tree pairs and absence of leftover transient directories. It restricts execution to CPUs 0–15 and eight build jobs. It preserves raw data and source under `work/pgo-intermediates/records/<arm>`, and it snapshots this recipe with SHA-256 hashes. Bootstrap captures or runtime work outside these scratch paths are unnecessary.

An instrumented Cargo binary and an optimized Cargo binary are retained per arm. Before exposing `bin/<arm>`, the audit verifies the exact seven candidate source files against that arm's commit, the independent merged profile checksum, all training inputs and successful invocations, both raw trace graphs, the unchanged static std archive, and the optimized executable checksum. The normalized unit-graph and std hashes must match the endpoint baseline. Only two temporary autocfg probe UUIDs are normalized, and their counts and exclusion from PGO are checked. `.pending` artifacts are private. `records/<arm>/ready.json` is the completion manifest. Full audit results also remain in `records/<arm>/audit.json`.

No artifact produced by an earlier Rust compilation is reused in a later generation or profile-use phase. Measurements can start once a readiness manifest exists. Native timing must account for other concurrent machine activity. The main run and intermediate runs intentionally preserve all failed attempts and have independent immutable records.
