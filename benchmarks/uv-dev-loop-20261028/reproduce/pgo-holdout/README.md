## What the release trained

| Component | Linux release behavior |
| --- | --- |
| Cargo driver | Cargo and rustc collect into a common raw-profile directory while running the release compiler workload. Cargo is rebuilt with the merged `rustc-pgo.profdata`. Bootstrap explicitly forces ThinLTO for Cargo, instruments with four indirect-value counters per site and normalizes static function names for both generation and use. |
| rustc | The rustc build consumes the same merged profile. The Linux job separately ran BOLT instrumentation and optimization on `librustc_driver.so`. |
| Standard library | Built in the pinned Rust tree with one codegen unit. Its bootstrap build takes the std-specific distribution profile. The tool-specific PGO flags are added to the Cargo/rustc consumer builds. We found no direct std profile-generation or profile-use build. Inlined or monomorphized std code can still participate in optimization in its consumers. |
| LLVM | The Linux coordinator passes `--build-llvm=false --llvm-shared=false --use-bolt`. It selects a matching CI LLVM. The optional local LLVM PGO/BOLT stages are gated on building LLVM locally. The Ohm job did not train a new LLVM profile. The precise prior optimization history of the downloaded LLVM binary is outside this audit. |

## Independent PGO protocol

The frozen source arms are `base` (above Cargo and std commits), `guard` (base Cargo, guarded std), `stack` (five Cargo patches, base std), and `guard-stack` (all six). The Cargo stack ends at `94c95d6b8ef97b0e63e04b250bc88d1a388a31af`. The guarded std patch has SHA-256 `ff2dcc74dfc56fb366422c29de08dc1baae4ec4efc91171069358b838177b795`. Each arm generates, merges and uses its own independent Cargo profile, at the same fixed source, target, raw-profile and merged-profile paths. All selection happens before timing uv.

The released rustc-perf gitlink is `0a054b0ead56e41a4584bfab6fdc1a5fad2aedc3`. The release selects nine crates and Check/Debug/Opt with all scenarios. The confirmation includes its `bitmaps-3.2.1` and `diesel-2.2.10` source trees, locked dependencies and upstream `0-println.patch` edits. Both configure the library target with no other Cargo flags. Together these fixtures contain 270 files and 2.07 MB. For each build mode, the instrumented driver runs a fresh non-incremental build, fresh incremental build, warm unchanged invocation and real incremental source edit, 24 Cargo invocations per arm. We use the release's LLD override during training. The released rustc remains fixed and the profile only collects Cargo. This is a separate, smaller training corpus and protocol than the release's joint nine-crate collector run. It excludes uv. [Pinned collector](https://github.com/rust-lang/rustc-perf/tree/0a054b0ead56e41a4584bfab6fdc1a5fad2aedc3) · [Official benchmark list](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/src/build_helper/src/lib.rs#L25-L36) · [Official invocation](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/src/tools/opt-dist/src/training.rs#L16-L51) · [Selected profiles/scenarios](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/src/tools/opt-dist/src/training.rs#L119-L121)

`wrap-rustc.py` mirrors the per-component flags while allowing `-Zbuild-std` for all arms. Cargo adds a synthetic `noprelude,nounused:std` edge to each target tool crate before appending the independent std graph. The wrapper applies PGO only to compiler invocations with this explicit target and marker and logs each decision. It supplies the released, `no_core` profiler runtime during generation. Each build starts with an empty target. A tiny two-phase smoke probe verifies runtime linkage, raw merging, covered symbols, the std boundary and profile consumption before compiling Cargo. `run.py` requires covered Cargo functions in every real profile. [Unit graph boundary](https://github.com/astral-sh/ohm-cargo/blob/a0c7d08c898d3fdff992f2f431dec57d2486add2/src/compiler/unit_dependencies.rs#L240-L272) · [Profiling runtime](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/library/profiler_builtins/src/lib.rs#L1-L15)

## Actual run

The first `work/pgo-confirmation` probe supplied only the released `.rlib` and failed before the Cargo arms. The release splits its Rust metadata into a companion `.rmeta`. The original failed log, target, and registry seed remain intact. `start-confirmation-v2.sh` starts a fresh `work/pgo-confirmation-v2` run, supplies both released artifacts, and verifies both prefetched training lockfiles offline. It confines the process to CPUs 6–31 and uses eight Cargo build jobs. [Cargo split-metadata linking](https://github.com/astral-sh/ohm-cargo/blob/a0c7d08c898d3fdff992f2f431dec57d2486add2/src/compiler/mod.rs#L3572-L3604)

The corrected probe compiled, produced a raw profile, merged it with LLVM 23.1.1, recompiled using the resulting profile, and printed `19` from both executables. Its real unit traces show one profiled application target and unchanged, unprofiled std and host builds. The release's `ToolStd` asks bootstrap to build std separately, then applies Cargo's own component flags to its tool build. Bootstrap passes an explicit target. Cargo documents that target rustflags exclude host-only build scripts and proc macros. [ToolStd](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/src/bootstrap/src/core/build_steps/tool.rs#L80-L105) · [Target argument](https://github.com/astral-sh/ohm-rust/blob/bfa236f639034f61ec884c15bd1f4e0b75e508ac/src/bootstrap/src/core/builder/cargo.rs#L611-L616) · [Cargo target flags](https://github.com/astral-sh/ohm-cargo/blob/a0c7d08c898d3fdff992f2f431dec57d2486add2/doc/book/src/reference/config.md#L594-L600)

After both binaries are ready, the retained experiment can be audited with `python3 work/pgo-holdout/audit.py work/pgo-confirmation-v2 work/ohm-cargo`. The audit reads the phases' actual unit traces, compares all seven changed Cargo files against their frozen commits, checks both executable and profile checksums and checks the SHA-256 of the rebuilt static std in every phase.
