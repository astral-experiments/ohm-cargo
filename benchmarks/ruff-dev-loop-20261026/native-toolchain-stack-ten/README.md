# Complete ten-Cargo and three-rustc native workspace checks

This study compares release-profile Cargo #242–251 plus rustc #230–232 with the unchanged release-profile Cargo and rustc bases. The command is an ordinary, unqualified `cargo +ohm check --locked --offline`, including its launcher and all compiler processes. The two historical patches affect a private parser implementation and the exported lexer in the same pinned Ruff workspace. Six Cargo jobs and all 16 CPUs of the isolated Linux benchmark guest are fixed. [Inputs, randomized schedule and acceptance criteria](plan.json)

## Experimental design

There are eight four-command blocks on the private edit and sixteen on the public edit. Each block is balanced against a linear time trend and has an independently randomized ABBA or BAAB orientation. Block order across edits is shuffled separately. The estimator is the median of the within-block geometric elapsed reductions. The exact two-sided test uses the mean within-block log ratio and enumerates all 256 or 65,536 allowed block orientations. We adjust the two predeclared endpoints with Holm. Both outcomes, including any neutral or regressive timing, are retained. The median intervals use binomial order statistics with at least 95% coverage. [Analysis](analyze.py)

The runner starts from the corresponding workspace and registry outputs warmed under separate toolchains in the earlier nine-Cargo study. Each observation makes a private, disposable copy of its own pre-edit store. The copy is switched to the stable canonical pathname, restored and checked fully fresh before timing. The private registry and verified compiler driver links remain at their original paths. The runner checks source bytes and timestamps, index, zero lock waits, the complete 520-unit feature and target graph, zero fresh-verification compilers, and the immutable seed manifests. It restores all source bytes and the previous toolchain selection. A qualification-only nine-Cargo run holds the candidate compiler fixed to screen per-unit metadata and API hashes when enabling the scheduler. The ten-Cargo treatment must select its own thread flags naturally from each prior dep-info file. No thread flags are added by the harness. ## Qualification and metadata

All six unscored restores ran zero compilers and all 520 artifact records were fresh before and after each edit. The private edit launched 35 control compilers and one treatment compiler. The public edit launched the same 35 compilers in both arms. Every control compiler used eight threads. The ten-Cargo scheduler selected one thread for the parser on the private edit and for 32 of the 35 public-edit compilers. The three remaining public-edit compilers used eight. Each decision was checked against the size of its actual pre-edit Cargo dependency file. [Per-unit thread flags](thread-decisions.csv)

The complete control and treatment use different compiler producers. The same set of 226 out of 442 raw `.rmeta` files differed across these producers before and after both edits. The same 197 of 435 public API cache files differed in all four comparisons. All sidecars retain Cargo’s version-1 JSON `{ "version": 1, "value": "<32 hex digits>" }` format. Within the control arm either edit changed 29 raw metadata files and 28 API values. Within each arm using the candidate compiler, the private edit changed only the parser metadata file and zero API values. The public edit changed 29 metadata files and 28 API values. With the candidate compiler held fixed, nine-Cargo and ten-Cargo outputs matched all 442 raw file digests and all 435 API values both before and after both edits.
