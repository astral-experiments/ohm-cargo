## Mechanism and correctness

In the initial graph, `Debug` and `Copy` made private parser implementation details reachable from foreign trait roots. A 20-line edit changed 2,110 of 3,570 retained definition fingerprints. The largest strongly connected component involved 1,599 definitions. The treatment keeps the complete candidate index and impl headers on the foreign trait and anchors eligible impl payloads to their private nominal self type. A check that can reach that type still incorporates the payload's fingerprint. The gate covers positive, unconditional, non-specializing impls with no type or const parameters and excludes auto traits. Macro exports, codegen, rustdoc, always-encoded MIR and opaque interfaces other than private ordinary function returns retain the conservative graph. All impl metadata is still emitted and available for precise queries.

A forced rebuild of all 35 affected work units was compared with the candidate's one-rustc cutoff. All 435 aggregate public hash files matched. Seven of 442 raw metadata files differed. A same-source pair of cold edited builds also differed on seven, with six files in common between the sets. Comparing warm and cold with no edit changed five. Across all differing downstream files, the production metadata listing and all retained per-definition and global RDR fingerprints agreed. The parser changed 435 retained private fingerprints identically on the warm and cold edit. The replacement compiler used to inspect per-definition entries was restricted to reading metadata, and its ordinary `-Zls=all` output was checked against the production decoder for every sample. The diagnostic decoder patch can be applied to a compiler built with the same version label, then used with `OHM_INSPECT_PER_DEFINITION_RDR=yes rustc -Zls=all FILE`. [Release metadata comparisons](metadata.json) · [Read-only RDR dumper](inspect-rdr.patch)

All 24 cross-crate guard cases compared warm results with clean results using incremental fingerprint verification. The cases cover inferred unnameable types, associated projections, private RPIT in public generic code, opaque auto traits, const evaluation, exported macros, trait-object dispatch, diagnostics and coherence. ## Replay

Use Linux, Python 3.11 or newer, bubblewrap, rustup's `cargo` proxy on `PATH`, an Ohm Cargo binary, a matching sysroot, and the two driver files. Each driver must sit in its own directory under its original `librustc_driver-*.so` name. Use a genuine clean linked Ruff checkout and a separate disposable, populated Cargo home with the sources for that revision. Flags shown here match the first production cohort. For the confirmation use four jobs, four pinned CPUs, 12 pairs and `--random-seed` from the confirmation plan. Setup and copying checkpoints occur outside the timed region. The runner checks the source revision, output graph, actual compiler count and driver used by each workspace compile. A fresh invocation of this portable runner independently reproduced the complete March case at 9.952 s (22 compilers) and 1.152 s (one compiler).

```sh
python3 replay.py discovery --before /path/to/ruff-93526150df \
  --sysroot /path/to/ohm-release14 --cargo /path/to/ohm-cargo \
  --control /path/to/control/librustc_driver-774a793a844d5500.so \
  --treatment /path/to/treatment/librustc_driver-774a793a844d5500.so \
  --cargo-home /path/to/private-populated-cargo-home --state /path/to/new-state \
  --jobs 6 --pairs 8 --cpus 20-31
```

For the full March patch pass `adjacent --before /path/to/ruff-67602512b6 --after /path/to/ruff-42cbce538b` and use a fresh `--state`. For the neutral case pass `public-lexer` with the modern checkout and `--pairs 1`. The actual Ruff source checkouts remain clean throughout the replay.
