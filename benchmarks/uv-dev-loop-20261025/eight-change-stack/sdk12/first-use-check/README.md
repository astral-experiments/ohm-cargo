# Cumulative Cargo first-use cost and warm-check payback

This separate endpoint compares SDK12 Cargo source `fdd26156` rebuilt by the matched stock producer with the eight-change tree `8a4b0c3c`. The baseline is source matched; it is not the literal shipped SDK12 Cargo executable. The candidate combines Cargo changes #231–235, #237, the two-choice registry-cache policy and the formatted single-parse change. `combined.patch` and `source-and-build.json` identify the complete source and actual binaries.

Each of two independent hosts contributes eight balanced paired dirty `cargo check` comparisons, with inverse orders and seeds 20261025325/326. Only the experimental registry-document cache starts absent. The native build artifacts, registry source and compiler state stay warm. Before each candidate command, its populated private cache is renamed into retained evidence outside the counted process. The baseline has no such cache. Both commands use `cargo -Zohm-defaults=yes check --locked --offline -j 8` and the same small source edit.

The metric is the Cargo parent process's final Callgrind instructions. Compiler and linker children run normally and their instructions are excluded. This is neither a whole-process-tree instruction count nor an elapsed-time result. Both full raw/restoration gates precede all 32 metric joins and both descriptive estimates. First-use results retain either sign, with separate paired 99% intervals and no host pooling or improvement requirement. The two warm endpoint packets remain separate.

Run `python3 reproduce.py` to verify every sanitized full profile, reconcile final/self/stderr counts and reproduce the first-use statistics. Run `python3 reproduce_amortization.py` to perform that replay and then independently compute each host's signed payback. Both use only Python's standard library. Path and command labels alone are sanitized; the nonpath cost stream is unchanged and its original digest is retained.

`counts.json` contains all first-use paired integer counts. `warm-counts.json` is an exact copy of the previously qualified same-host warm-check counts, also retained with their full profiles in the [warm-check packet](https://github.com/astral-sh/ohm-cargo/tree/d9310610fa4fa6e2b9c40213b8e0979125cf7973/benchmarks/uv-dev-loop-20261025/eight-change-stack/sdk12/warm-check). `paired-counts.csv` makes both phases easy to inspect. The amortization denominator is the same host's mean paired warm saving; the numerator is its mean paired first-use candidate-minus-baseline cost. Additional warm checks equal `ceil(max(0, cost / saving))`. Negative net first-use cost remains negative in the descriptive estimate and implies zero additional checks. Independent paired resampling within each phase yields the separate ratio interval; no per-PR percentages are added.

Payback is a model between separately measured cache conditions. The warm denominator comes from the mixed check/test-build bank with 507 committed entries (902,046 bytes). The excluded first-use preflights ended with 467 entries (844,980 bytes), after retaining 507 entries before the native capture and 469 before the instrumented capture. These are not a measured sequence of immediate check-only invocations after a cold check. The estimate is a number of the separately measured 507-entry warm checks. `cache-conditions.json` retains these distinct excluded observations; numbered per-call inventories are reported separately without assuming a fixed entry count.

`cache-write-lower-bounds.json` reports each sample's final committed slots and bytes. These are lower bounds on creations and logical writes because replacements and temporary writes are absent from a final inventory. They are not physical-I/O or total-write measurements. Full retired cache payloads and post-command typed inventories remain in the private collection; the witness does not independently recompute the keyed BLAKE3 codec checksum.

The public packet contains full sanitized profiles, integer counts, numerical replay, source/build identity, protocol and custody digests. Private command environments, host names and transport records remain private. Each arm still requires its freshly admitted output hashes and full compiler context; the first-use endpoint adds no general output mask. Previously ineligible cohorts remain excluded and unopened. The matched source/functional gates and both qualified warm outcomes are prerequisites to this separately labeled endpoint.
