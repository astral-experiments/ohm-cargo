# Ruff formatter check, build and test-build transitions

Packaged Linux Ohm 1.99.0-16 compiled the full reversal of Ruff change `1fcdb82be0169fc79f492f03728f52215af563c0` in two private, independently settled `-p ruff_formatter` states. Each used a common checkout, target and registry path under a private mount. One state began with check → build → test --no-run → build. The other began with build → test --no-run → check → build. An independent empty edited state supplied the third reference. The complete sample covers 56 genuine Cargo commands.

On the first edit and its restoration, either ordering ran exactly three full compiler invocations and one Wild link across the four commands. Check emitted changed compiler metadata. Build emitted both a changed rlib and changed metadata. Test compiled and linked a changed harness. Every last build in those four edit/restoration cycles was already completely fresh, as were all 16 unchanged post-edit and post-restoration controls. The package has 57 Cargo unit reports in check and build and 58 in test-build.

The check result depended on command order. Seven of eight direct compiler inputs had different paths and bytes in the two selected check units. The build compiler argv matched across orders. Its direct `ruff_text_size` input bytes differed. Test argv matched while three of its fifteen direct input slots differed. The two edited harnesses nevertheless matched the independent edited harness byte for byte. The two ordinary edited library outputs (rlib and rmeta) differed from the independent cold outputs. The product tables preserve these cold and incremental differences.

A newly compiled external caller received E0425 for `ruff_formatter::format_element::LINE_TERMINATORS` with the original source, compiled successfully with the reversed source and received the same E0425 on restoration. A native external program normalized CR, CRLF, U+2028 and U+2029 to the expected four outputs in every non-check command. The actual 30-entry formatter harness list was unchanged. Its existing `format_element::tests::test_normalize_newlines` test passed outside each Cargo test-build. Cargo itself always used `--no-run`.

The three archives hold command status, typed artifact rosters, before/after content and mtime fingerprints, compiler and linker argv, preserved native-file hashes, and direct caller diagnostics.
