# Ordinary Rust metadata readers across two histories of identical Ruff source

This is a diagnostic check on the same native build stores used for the held-out Ruff experiment on H5. Both Rust #232 and corrected #233 initially built unmodified Ruff, compiled the historical lexer change, then restored the complete original source. Within each release the parser in both original states had identical source file digests and stable crate ID, but different private and public hashes in its metadata. Each captured .rmeta was retained at the time of its corresponding fully fresh cargo build. The capture file includes the source and actual compiler identities.

For each release an ordinary rustc +ohm command produced a small bridge against each captured rmeta. Two further caller invocations consumed the bridge with its original parser and two consumed it with the alternate history's parser. All four producer and same-history commands for each release succeeded. Both crossed combinations failed with rustc E0463 on both releases. This probes manual artifact substitution between otherwise successful Cargo histories. Cargo rebuilt and read the artifacts within each history successfully.

The final reader gives rustc the actual Cargo search path list of the ruff_linter producer and projects every search directory that contains a parser library. Within those projections the captured rmeta is the only parser library available. Syscall traces show the exact parser opened by every producer and caller. The projection avoids a neighboring live rlib accidentally satisfying an old dependency. The earlier unrestricted control retained in the JSON illustrates that ambiguity, including one successful crossed #233 reader. Two preparatory attempts using stricter projections stopped on an overly restrictive spelling of the native path and an assumption about the diagnostic code. The recorded final reader accepts the exact logical or resolved physical file, retains the complete real diagnostic and requires a successful produced artifact on matched histories.

Run python3 -B verify.py to check all 12 ordinary compiler results, input identities, source equality, decoded metadata roots, actual successful opens and raw diagnostics. The primary paired Cargo timing study uses its own complete, isolated stores with no manual artifact substitutions.
