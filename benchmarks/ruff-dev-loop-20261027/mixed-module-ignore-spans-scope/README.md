# Producer-only span ignoring and an ordinary-writer fallback

This is a separate unscored option-compatibility experiment on Linux x86-64. No product source changed. The reference images are released Ohm -17 (`618ebac1…`), its matched corrected default-mode compiler (`748e5862…`), and ordinary upstream stable Rust 1.99.1 (`58cf8f9c3`).

An explicit producer-only `-Zincremental-ignore-spans` leaves a span-sensitive reader. The possible fallback under test would select `public_api_hash=false` in the producer during option construction. Direct rustc selected those exact effective producer and reader choices. A genuine Cargo profile selected them independently in an ordinary two-crate workspace with source available.

The original fixture both moved the declaration and changed its body from 17 to 29. Selecting the ordinary writer fixed that fixture because its full crate hash changed. Keeping the function text byte-identical and adding eleven spaces before it falsified the general fallback. On the fixed compiler, the ordinary producer’s hash was identical across the edit, the warm reader panicked in `module_children`, and an empty reader succeeded. Native source-available Cargo independently returned 101 on the warm edit and built a working executable from empty. In that same native Cargo fixture both current default writers and explicitly requested native RDR passed, and the proposed ordinary writer turned both into failures. The direct metadata-only configuration has different existing protection and is shown separately.

On upstream stable compiling both crates without RDR, the native reader check did not panic in this pure-position control. Its warm producer reused the byte-identical original .rmeta. A separately invoked erroneous caller reported the previous declaration at column 8, with no source line. Empty producer metadata reported the new declaration at column 19, with the actual text. On Ohm the refreshed warm producer metadata gives that independent erroneous caller the correct column 19 while the warm incremental reader panics.

`python3 verify.py` checks the observed data. To replay the pure-position falsifier, run `python3 reproduce.py ordinary-writer` with Ohm -17. The corrected default producer passes `python3 reproduce.py normal`. To repeat the upstream condition, point a private rustup alias named `ohm` at ordinary upstream stable and run `python3 reproduce.py upstream-ordinary`. The bootstrap environment in the upstream condition permits its explicitly unstable span-ignoring option. Each invocation uses private directories. No timing inference was made.

`controls.json.gz` contains exact compiler bindings, captured per-command and output SHA-256 digests, recorded direct producer/reader argv and statuses, compiled and executed Cargo behavior, typed Rust invocations and diagnostic spans. The main default-mode repair has its own independent source and result packet.
