# Stock Wild’s pre-layout capture and a Rust jobserver probe

Ohm packages the Wild executable itself at `wild-ld/ld.bfd`. Cargo gives the system C compiler a `-B` prefix and selects `-fuse-ld=bfd`. The existing Rust shim at `gcc-ld/ld.lld` only dispatches LLD. A Rust shim placed at the Wild path in a private copy received the final arguments from GCC's real collect2, including the linker-plugin path and the generated resolution file. The packaged stock Wild was hash-checked at `0d633580…` before the tests. [Cargo’s link selection](https://github.com/astral-sh/ohm-cargo/blob/7caf39914da1e28a67744ecbc963a5f26361474d/src/compiler/ohm_linker.rs#L52) · [Rust distribution](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/src/bootstrap/src/core/build_steps/dist.rs#L591) · [LLD shim](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/src/tools/lld-wrapper/src/main.rs#L58)

In ordinary full links, adding an archive in an earlier search directory changed the program's exit from 41 to 83. Stock Wild’s `WILD_SAVE_DIR` plus `WILD_SAVE_SKIP_LINKING` distinguished these two sets of files. A missing or malformed library still returned 0 from save-only mode. With an auxiliary version script found through `-L`, valid, malformed and missing source produced the **same complete saved pathname and content map** and the same successful save status. Ordinary Wild succeeded only on the valid input and returned separate parse and missing-file diagnostics for the others. The diagnostic exits before checking the FileLoader result, reading the auxiliary script and validating inputs at the end. [Stock link ordering](https://github.com/wild-linker/wild/blob/e856d81f6683cad80b9fe0ebf1a0c3c403c6fe11/libwild/src/lib.rs#L323) · [Auxiliary file search](https://github.com/wild-linker/wild/blob/e856d81f6683cad80b9fe0ebf1a0c3c403c6fe11/libwild/src/input_data.rs#L255)

With identical actual Wild argv and object bytes, zero and three available jobserver tokens produced two different full ELFs. Both returned 42. The saved file map, including `run-with`, was identical. Direct save-only execution drained all three offered tokens without returning them. Both default fork and `--no-fork` reproduced this. A small Rust wrapper used the same jobserver crate to hold the tokens, passed the effective worker count to the stock child and returned every original token byte. Through ordinary GCC/collect2 the 1- and 4-worker executable hashes each matched their direct controls. These successful width checks establish no native cache hit. The simple GCC fixture used `-nostdlib`, and the packaged source compiler and real Ruff measurements have separate provenance.

The prior physical `ty_server` e2e recipe also produced two ordinary ELF hashes from its same 411 positive inputs. A single worker produced `b9fe6451…`. The other fifteen tested widths produced `d999e50c…`. Its two differences were the GNU build ID and the `.rodata` entry-size field. These are historical data for that precise recipe. The new release SHA, actual external callers and additional 49 terminal targets require their own qualification. [Historical raw native results](https://github.com/astral-sh/ohm-cargo/tree/a75e5f17/benchmarks/ruff-dev-loop-20261027/rc17-composed-early-native-results)

Run `python3 -IB verify.py` to check the portable observations. On x86-64 Linux, `python3 -IB probe.py /path/to/stock-Wild /new/private/dir` repeats the native cases. In `width-probe`, build with `cargo +ohm build --locked --offline`. Run `python3 -IB wrapper-test.py /path/to/stock-Wild /path/to/width-probe /another/new/private/dir` for the GCC controls. The dedicated jobserver belongs only to the fixture. There are no whole-command timing samples.
