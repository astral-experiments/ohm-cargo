# Pre-measurement resolution of the active Ron unit

The original full-Ruff prefetch experiment stopped after its first test anchor. It ran zero scored commands. Under the trusted namespace the first control preparation built 501 build units and 619 test-build units. The candidate then rebuilt 56 logical test units as it trained the reader. The next control test command reported all 619 fresh, with two complete Ron dependency-info records retained in different target directories.

The new study preserves the 16 balanced pair orders for each full command, Cargo/rustc release binaries, physical trained target and shared directories, repository, default host-local flags, jobs, CPU affinity, wall-clock endpoints, paired tests and rejection rules. It takes a private copy of the established Cargo-home proof payloads, then requires all eight preparation and anchor processes to be fully fresh. New output directories preserve the earlier failure.

The separate compiler-artifact binding uses the single normal Cargo library from the pinned ron 0.12.0 with its exact package, features, profile, target and filename list. The active .rmeta must be in the same physical output directory as its rustc dep-info and the same Cargo unit as its complete translated OBS1. Two actual prior rustc processes advertised this exact out directory. Both the active and separately identified dormant records must retain their complete BLAKE3 footer, raw and encoded SHA-256, metadata, inode, size, mtime, and ctime throughout qualification and scoring. Every native timed command has pre/post checks. A separate ordinary fresh JSON/process audit at each scheduled slot must resolve the same active identity. Unknown physical readers, ambiguous Cargo advertisements, changing passive data and stale work each fail the study.

The program first writes a four-anchor certificate without sampling. Scoring requires a later explicit grant containing that certificate's SHA-256 and the immutable registration. It reruns the guards, completes the original all-arm schedule and reports both endpoints even if the effect is inconclusive. Recovery from a missing active record still happens on independent copies after scoring, preserving physical passive bytes on each clone.

Run `python3 -B make-v2-registration.py --verify`, `sha256sum -c SHA256SUMS` and `python3 -B test-active-records.py` to verify the runner. The previous study's complete plan and original statistical acceptance rule are included in ruff-prefetch-registration.json.
