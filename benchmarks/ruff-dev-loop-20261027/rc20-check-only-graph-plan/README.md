# Cargo check after a Ruff dependency edit

This single-host Linux protocol measures ordinary Cargo checks after changing whether `ruff_python_trivia` directly depends on `unicode-normalization`. Ruff changed its manifest, lockfile and real name-matcher implementation together. The native caller returns `true` with the older code and `false` with the newer code for `NameMatcher::new("C").may_match("# café")`. The patch applies in both directions to the pinned workspace. [Ruff change](https://github.com/astral-sh/ruff/commit/f240bf849841cf6cb3ffd844db8bd6d6aa0b3026) and [Ruff checkout](https://github.com/astral-sh/ruff/commit/93526150df078af7dd8fc4226cdcc469539d2001).

The control is Cargo `8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b`. The treatment `ec660ad8b5f3327924988ef3daa9e4444106b40e` changes when Cargo consults its hint for an existing ordinary check graph. When no native registry build is ready and the caller has not explicitly requested reuse, normal selection already produces the ordinary graph. The treatment retains a separate readiness check for normal selection if the speculative ordinary check was actually attempted. The two release builds use the same PGO data and native dependency order. The timed workspace uses the same released Linux Ohm -19 Rust compiler, standard library and bundled Wild in both arms. [Existing graph hint](https://github.com/astral-sh/ohm-cargo/pull/170).

## Native qualification

Eighteen unscored checks used per-process kernel exec traces and Cargo's build-analysis resolution events. Each old-to-new edit builds four crates on both arms. Each new-to-old edit builds only the Ruff library on each. These two edits resolve twice on the control and once on the treatment. Changing only the genuine name-matcher source while retaining the newer manifest and lockfile compiles the Ruff library and resolves once on each arm. Every independent settled or immediate unchanged check resolves once and runs zero compilers. All checks run zero linkers.

Every compiler artifact, ordinary metadata filename and payload matched across the paired qualification. Rust chooses a fresh timestamp, nonce and hash in its private incremental-session directory on separate compilations. Comparison keeps the enclosing crate directory literal and compares the complete ordered name, length and SHA-256 contents of each session as a group. The original literal manifests are in `native-states.json.gz`. Initial qualification stopped on literal session names, then verified the refined rule before collecting any timing. A separate initial collector omitted split syscall returns in concurrent cold runs. Its preserved raw traces were independently decoded by PID. The subsequent 18 anchors used a separate trace file per process.

The live caller checks give `false → true → false` on the reversal and restoration. Combining the newer matcher with the older manifest gives E0432 on both warm checks and both independently empty checks. A separate feature-edit fixture gives E0308 on both arms and both immediately repeated invalid checks. It verifies explicit reuse, a real marker established by a native build, and aggregate opt-out on a common released -18 compiler. All 13 existing workspace-resolver tests passed against the treatment. The control failed the pre-existing semantic-RUSTFLAGS test and the new graph-count regression. Two other existing test fixtures stopped at exactly the same hardcoded missing-marker or missing-fingerprint assertions on both binaries. The actual local markers, input traces and test list are recorded.

The four independently trained check-only stores all had an ordinary graph hint and no native-ready marker. A separate package build wrote its target marker for each arm, and a retained full Ruff test build had both target and shared markers. This identifies the relevant workflow. The sample does not estimate how many users or repositories have that state.

## Frozen measurements

- Use 16 randomized four-pair blocks. Within every block, each direction occurs once A-first and once B-first. Analyze the 32 chronological and 32 reverse pairs separately. Then run eight counterbalanced two-pair blocks of the source-only edit as a guard.
- Every arm starts from a new private ext4 copy of its own fully check-warmed state. The source, build directories, toolchain alias and active Cargo path are identical inside the private namespace. Verify the seed's filename, contents and symlink manifest before and after each copy. Keep Cargo's existing compiler, linker, locking and incremental settings.
- On that copy, bracket one fully settled check *before* the edit. Apply the three historical files, their reversal or the registered source-only change outside the clock. Independently bracket the edited check and the immediately following unchanged check. There are 80 pairs, 160 independently restored arm states and 480 Cargo subprocesses. The command is `cargo +ohm check --locked --offline -p ruff_python_trivia --message-format=json`. The stopwatch spans the rustup invocation through Cargo's exit. The scorer uses monotonic raw time, eight fixed eligible CPUs and ordinary-user permissions. Workspace staging, file verification and namespace startup are outside the stopwatch. Tracing and build-analysis logging run only for the unscored anchors.
- Each timed invocation must exit successfully and return the exact qualified typed artifact/freshness roster. The initial seed, per-arm compiler metadata and post-edit artifact bytes must match the independently measured native anchor. After the 80 pairs, repeat all six three-phase native sequences and check actual compiler, linker, graph and metadata identities. Preserve the first operational or semantic failure. Do not score an incomplete experiment, reallocate pairs or add runs after examining effects. Both disk volumes must retain 24 GiB plus a 256 MiB stop margin. Check for other builds, linkers and profilers before and after each pair.
- The co-primary estimands are the per-direction median paired reduction in the edited check, `1 − B/A`. Use two-sided exact sign flips of the 16 block means of log(A/B), then Holm-adjust the two p-values. Report two-sided percentile 95% intervals by resampling whole blocks 20,000 times. Report raw A/B medians, paired milliseconds, faster counts and the edit-plus-next-check result alongside them. The settled check and immediate unchanged check are distinct endpoints. The source-only result has its own paired interval.
- A standalone PR requires both edited directions to save at least 2%, with positive lower confidence limits and Holm-adjusted p below .05. In each direction, the settled and immediate unchanged checks must each rule out both a 3% and a 5 ms regression at the lower confidence bound on savings. Both edit-plus-next-check median reductions must be positive. The source-only edited guard must rule out the same 3% and 5 ms regressions. Results are scoped to this toolchain and host.

Run `python3 -IB verify.py` to recheck the frozen inputs, schedule and native comparisons. A terminal timing projection has one record per declared pair, with integer nanoseconds for settled, edited and immediate repeat in that order within each arm. Recompute with `python3 -IB analyze.py order.json pairs.json`. This plan contains no timing samples.
