# Can Cargo omit the fifty native links after recompiling ron?

On the first three unchanged Ruff test-build commands, all 150 actual Wild invocations searched for seven dynamic libraries, received five system startup objects and used the GCC LTO plugin option, dynamic loader and multiple project, SDK and system search directories. The first search is rustc’s per-command raw-dylib directory. The first non-temporary one is the psm build-script directory in all 150. No target qualifies for a pure Rust or no-native-search shortcut. Thirty-five individual links in each command explicitly name the ron archive. The other fifteen still perform these same native searches. The original 619-unit experiment includes the genuine Cargo, compiler and Wild process receipts and checksums. [Three native rosters](https://github.com/astral-sh/ohm-cargo/tree/af96bf0897584ffacf23dd7cc7a99282b96af9c6/benchmarks/ruff-dev-loop-20261027/corrected-ron-output-repetition)

A small independent GNU C driver fixture recreated each of the three project-library search-directory patterns and the seven dynamic library names with packaged Wild at fixed width one. We kept every previously reported dependency byte-identical. An earlier libgcc_s.so script under the psm directory selected an additional object and changed the running program’s exit status from 41 to 83. An invalid replacement made the real link fail. Removing it restored the exact original ELF and exit 41. All twelve successful Wild process launches (including the three links which then returned an error) were physically traced. The historical Ruff formatter’s zero-test harness also changed from returning 0 to exiting 83 on an earlier libgcc_s.so while its Rust objects stayed constant. These are correctness controls, with no wall measurement or inference that an earlier shadow normally exists. [Ruff formatter control](https://github.com/astral-sh/ohm-cargo/tree/ad38789312a620c82df6ef588757f8e633194194/benchmarks/ruff-dev-loop-20261027/formatter-bin-harness-link-observation)

Cargo’s current relink manifest authenticates cached Rust codegen data. It does not retain the ordered native search resolution or earlier missing candidates. The released linker’s Make depfile can enumerate chosen files but does not preserve absent search names, driver selection/side outputs, or all temporary plugin inputs. A safe optimizer must rerun native resolution or capture and revalidate the actual ordered resolution, including driver specs, nested scripts/relative operands, active plugin and native helper context, file identity/DSO names, outputs and other requested effects. Unknown forms must execute the original link. The earlier experiment measured 95–500 MB of selected bytes across one target in each family, providing a cost check separately from this correctness control.
