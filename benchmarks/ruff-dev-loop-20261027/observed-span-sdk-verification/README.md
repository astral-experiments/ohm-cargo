# Standard-library inputs to a foreign procedural-macro span reader

The unchanged Cargo command read each of 39 SDK files once for checksum validation in this fixture. Nineteen metadata files accounted for 88,319,067 bytes, their 19 static archives accounted for 9,003,780 bytes, and the shared standard library accounted for 1,579,704 bytes. `libcore.rmeta` alone accounted for 54,266,935 bytes. The compiler’s binary dep-info implementation visits every crate in the session and records each available metadata, static-library and shared-library variant. The implementation of these extra checksum calls is in `rustc_interface::passes::write_dep_info`.

A real stable procedural attribute receives the generated `const` token from `std::thread_local!`. The resulting native program prints its SDK filename, line and raw span. Under a private mount, two equal-length filename substrings in the copied `libstd.rmeta` changed its reported filename from `library/std/src/thread/local.rs` to `library/std/src/thread/local.xs`. File length and mtime, on-disk Rust source, compiler version and executable paths were identical. The trained unchanged build started zero compilers. After the SDK mutation the trained Cargo recompiled only the reader, and its successful native output equaled an independent empty build. The program read the same line 284 and raw byte range 247720 to 247725 on both SDKs. This controlled metadata edit establishes a real semantic dependency on authenticated SDK bytes.

The separate eight-pair calculation in `sdk-primitive.csv` checks the same 39 complete files with 64 KiB read buffers and BLAKE3 1.8.5. The first group contains the metadata misses of the intermediate reader. The second group contains the remaining native-library misses of the terminal reader. Serial verification took 49.62 ms at the median, and verification with one helper for the largest metadata file took 33.18 ms. All eight primitive pairs favored the helper. Its median paired reduction was 33.92%. These are local checksum-only diagnostics. `sdk-proof-agreement.json` verifies that all resulting digests matched the actual compiler dep-info checksums.

`sdk-span-control.py` imports the `paired.py` harness and fixture from the registered observed-span dirty-dependency study. Run it alongside those files with the same `--state`, `--driver`, `--parent`, `--candidate`, and a fresh `--work`. Use the earlier strict-receipt Cargo or its compatible successor as the candidate. The helper replaces the installed metadata only inside a private read-only bind mount. It writes all generated sources and artifacts to that new temporary directory. `sdk-span-causal.json` contains both SDK content digests, the native outputs and actual compiler modes.

For the checksum diagnostic, build `sdk-verify-primitive` with release optimization and run its executable with the matched SDK’s `lib/rustlib/x86_64-unknown-linux-gnu/lib` and `sdk-inputs.txt` as arguments. The recorded commands used four pinned cores and at most two threads. On this filesystem the kernel returned `EOPNOTSUPP` when queried with `FS_IOC_MEASURE_VERITY` for `libcore.rmeta`.
