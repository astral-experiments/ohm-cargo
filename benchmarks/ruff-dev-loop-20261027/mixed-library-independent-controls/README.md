# Guarded links for libraries producing both an rlib and a cdylib

An independent stage-1 compiler built a library consumed by a C program through `dlopen`. Changing an upstream function, restoring it, and changing it again made the C program return 100, 94 and 100. Each command launched one compiler on the library, retained the saved code-generation recipe and linked the new code. The final independent accepted edit returned 121. The Cargo and compiler identities are recorded in the archive.

Changing `env!`, an included byte or procedural-macro output forced a full compile. Replacing a saved object with different bytes at the same length and modification time also forced a full compile. That case returned 116 from both the warm and independent clean binaries. The shared library and embedded Rust metadata were byte-identical. The two raw rlibs differed at exactly two appearances of the generated native member filename. Renaming just that member made every byte agree.

Two previous implementations missed an explicitly requested MIR output on three consecutive edits. The guarded Cargo recognized the workspace compiler wrapper and the final compiler regenerated the MIR file on all three. Its contents matched a clean build. Replaying the same unwrapped compiler invocation with an additional MIR output independently produced the file and forced the compiler to take the full path. Warning diagnostics matched on all six phases. The new Cargo and older compiler also compiled the edit normally.
