# Reconstructing one real Ruff parser rlib from already-compiled native objects

During a different untimed repetition of Ruff #26526, the released Ohm 1.99.0-18 parser compiler acquired 80 regular files before it published the new rlib. A ptrace observer selected only the genuine full `ruff_python_parser` rustc in an ordinary workspace build. It preserved the 78 native inputs and `lib.rmeta`/`lib.rmeta-link` at their actual successful read-only open, before the final archive rename. The prior incremental session already held all 78 native `.o` files. Every current object descriptor matched its prior work product on full SHA-256, device and inode. All 78 current member names differed from the previous archive. `lib.rmeta` contained the genuine independently emitted current 1,350,596-byte standalone metadata at offset 96. The link wrapper specified the actual order and names of all 78 Rust objects. [Ruff change](https://github.com/astral-sh/ruff/commit/1e9287d7654f1dbe4943d67ed5ac5363c9ee2161) · [Released compiler’s wrapper and object handling](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/back/link.rs#L554)

A private mount namespace gave LLVM’s ordinary deterministic GNU archive writer access to the two current metadata objects, the 78 previous native objects under the current names, `/usr`, its loader cache and an empty output directory. Both historical and current finished archives were inaccessible to that writer. Its 6,010,742-byte output was byte-identical to the released rustc output, `767604cde0b5f1c5845ff0a9d2de9faed20e9debfae814a981549730cafef9e1`. A second constructor independently regenerated the long-name table, used the prior fixed-width GNU headers and symbol index under guarded same-size, same-order, same-object conditions, inserted current metadata, and matched every byte too. Substituting the old metadata, old link wrapper, or old archive long-name table yielded three distinct incorrect digests. The ordinary external Rust reader linked against either the stock or rebuilt rlib produced the exact same ELF and all four expected edited answers. [Released compiler archive writer](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/back/archive.rs#L545)

This is a native packaging proof for one parser build. The stock compiler still ran its frontend to produce current metadata, checked the actual codegen work products, and published its normal archive. The current acquisition read 4,464,192 bytes from native objects and acquired 1,357,832 bytes of wrapped metadata. Inode and byte comparisons here establish what happened in this isolated capture. An external-writer-safe general cache would need a stronger acquisition contract. An implementation wholly inside one rustc invocation could instead keep separate logical archive member names and true physical CGU inputs and retain the current writer’s normal acquisition checks. No performance measurements or product changes form part of this packet.

Run `python3 -IB verify.py` and `sha256sum --quiet -c SHA256SUMS`. The native replay uses the worktree, `prime.py` and `snapshot.py` from the full historical source packet, followed by the included `trace_archive.py` and `reconstruct.py`. Put `archive_observer.cc` in `$FSTRING_ROOT`, use the same private environment variables as `reproduce/run.py` in the historical source packet, and make its `reproduce` directory available on `PYTHONPATH`. The raw stock session, compiler FD captures, public symbol table and private previous/current archive bytes remain on the acquisition host. The first observer’s optional successful-link string count is a lower bound; it recorded complete strings for 37 new object names. It did not trace unlinks. All 78 compiler-read native descriptors were independently authenticated against the previous input device and inode.
