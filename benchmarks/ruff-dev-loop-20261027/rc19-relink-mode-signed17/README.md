# Released Linux Ohm -17 accepts an invalid relink-mode transition

A procedural macro observes whether its rustc received `-Zemit-rlink`. The fixture builds a consumer through a facade with three ordinary offline workspace crates. It switches Cargo to `-Zrelink-only=no` without editing source. The official [Linux -17 release](https://github.com/astral-sh/ohm/releases/tag/ohm-1.99.0-17) is the sole SDK used.

Both default-to-no and explicit-yes-to-no returned success twice and the executable printed 17. None of the four commands invoked a compiler or native linker. Moving aside only the consumer's 16-byte Cargo fingerprint made each next no-mode build invoke rustc and exit 101 at `consumer/src/main.rs:1:28`. Both independently empty no-mode builds emitted the same diagnostic, `link recipe was not requested`. Both positive-mode restorations and the empty arm's recovery invoked the packaged linker and produced the same complete executable.

The first acquisition reached its 60-second tracing limit before reporting a row. The detached Cargo subsequently reported a successful cold build. Its traces and exception are retained separately. The completed 17-command acquisition started from a different empty directory, with the same source, executable identities and timeout. The only edit to the supplied fixture changes its host storage guard from 45 GiB to 24 GiB and preserves the additional 600 MiB headroom.

Run `python3 -IB verify.py` to check the portable rows, executable receipts, expected errors and repeat work counts. Passing the separate original trace tarball as the sole argument also verifies the unmodified receipt files, diagnostic output, source bytes and two escrowed fingerprints against the recorded SHA-256. The original tarball is retained privately because the command lines contain host-local paths. To reproduce against an extracted official release, run `python3 -IB reproduce.py NEW_EMPTY_PATH SDK_DIR CARGO_SHA RUSTC_SHA` with the two full hashes in `verified-native.json`.
