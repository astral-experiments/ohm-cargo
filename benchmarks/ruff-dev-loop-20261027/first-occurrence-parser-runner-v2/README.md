# Unscored first-occurrence runner

The immutable [historical patch plan](https://github.com/astral-sh/ohm-cargo/tree/7ef4e84e3838cabd8e713fcadef6347a67f9fc00/benchmarks/ruff-dev-loop-20261027/first-occurrence-parser-plan) predates this adapter and every modified workspace command. This comparison records the first physical response to three different parser reversals on the exact same release compiler. Each arm warms on the original only, restoring the original after each patch.

Eight classifier, namespace, artifact and caller modules plus their import-time legacy plan are byte-identical to the audited mixed-workspace worker. The legacy source setter, schedule, expected process counts and timers are never called. The additional command-line fixtures and all changed paths come from novel-plan.json. The runner exposes the successful executable images and raw traces for the Cargo command, explicit recipe before/after identities, complete Cargo JSON and a separate external output inspection. A guarded rustc with unchanged authenticated recipe remains a real partial compiler process.

An independent tiny Git pack includes the six historical parent/child commit objects and the changed ancestor tree objects. The worker reads the complete original diffs in a new private bare Git object database, so H2’s shallow pinned Ruff checkout remains untouched.

novel_state.py reverses the complete historical patch once to create each source image and checks the original Git commit and blobs. Three Rust files have independent private bind mounts. The two directories containing deleted signed-pattern artifacts are copied privately and mounted exactly, so the two files disappear on reversal. The current source setter never rewrites an unchanged source. rehearse_novel.py checks patch contents, untouched mtimes and all seven transitions without invoking rustc or Cargo.

novel_worker.py runs the ordinary default full workspace command with j8 and only JSON output selection under strace. Cold, edit, restore and initial-settled phases decode each mixed metadata header, audit its raw archive and native symbol table, open its native exports, and hash every workspace ELF. An immediate unchanged invocation requires zero real compiler/GCC/collect2/Wild work, all 501 / 619 units fresh, identical complete output bytes, and the expected Ruff CLI at both command boundaries. The CLI positive and negative inputs, including both changed signed-pattern diagnostics, come from the historical plan.

novel_run.py checks the frozen H2 tools, exact Cargo and compiler digest for both arms, its CPU affinity, clean real repository and recorded Git index before a nonblocking exclusive native lock and cold stores. In the actual code the binding and host checks precede acquiring the lock and the source check happens under it. It reserves at least 25 GiB throughout worker execution. Starting a build requires 40 GiB and starting separate cold test arms requires 60 GiB after both build arms are entirely finished. This run derives no elapsed-time summary. Any reserve or command failure is terminal and no input is rerun automatically. Each candidate’s two mixed producers have their rmeta, archive, exported entries, C ABI, and direct plus cross-arm ordinary Rust bridge callers recorded. Cross-arm product differences are retained. A failed ordinary bridge bounds the claim and remains in raw diagnostics. Both arms must meet the same normative Ruff CLI assertions.

The results live only in the new physical directory first-occurrence-mixed-parser-20261027. The root reviewer supplies a release JSON containing the binding SHA, phase unscored-first-occurrence and plan URL. Start the frozen runner from the authorized H2 session with taskset -c 0-23 python3 -B novel_run.py --release approved.json. A partial run is preserved and refuses a restart in the same directory.
