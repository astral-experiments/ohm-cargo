# Where the previous Ruff archive survives

For **all 31 downstream rlibs** whose native objects stayed byte-identical, Cargo removed the old compiler output *before spawning that library’s rustc*. The edited AST producer made a 32nd example. In these default-workspace builds, all 32 had a separately named, public rlib under target/debug. This previous top-level file survived the unit-file deletion, and Cargo unlinked it and installed the newly compiled version after rustc returned. The resulting public and per-unit files had the same device and inode for all 32 units. The per-unit incremental directories held no complete .rlib when inspected. The archive writer therefore could not have cloned any prior rlib by opening its own current output pathname.

For parser, formatter and linter, the Cargo worker’s pre-spawn unlink was its second, third and second recorded syscall respectively. Its rustc spawn was the sixth, seventh and sixth. Their current tmp.a files were renamed by genuine rustc worker threads. The subsequent successful unlink and hard link of each public output occurred on the original Cargo worker. The per-thread line sequence, process creation edges and successful filesystem calls establish the relevant ordering without cross-thread timestamps. The independently recorded preceding Cargo command reported exactly the same 32 public rlib paths. The pre-spawn trace did not record the old public files’ byte digests at that instant; an old filename's presence supplies no proof that its contents are eligible.

Released Cargo removes an old .rlib next to an emitted .rmeta before invoking rustc to prevent downstream consumers from accidentally preferring the older archive. It also removes pre-existing regular outputs before compiling when it has an uplift destination. After a successful unit, Cargo installs its new top-level link. Directly requested build roots qualify for a public rlib, whereas ordinary rlib dependencies do not. Nine independently retained real commands selecting only ty_vendored each reported 148 rlibs. Only ty_vendored had a public path. Cargo reported ruff_python_parser exclusively at its per-unit compiler output path in all nine. Both corresponding populated stores had exactly one top-level rlib on disk and lacked the public parser name. These commands traced process creation and opens, and omitted unlink and rename; the workspace evidence provides the actual pre-unlink observations. No targeted ruff_linter command on the historical edit is part of this evidence.

For an additional archive-geometry bound, each individual source work-product .o starts at file offset zero. The equivalent destination range inside 31 actual edited archives began at a multiple of 4,096 bytes for only two of 4,306 complete native objects, both in ruff_db. These could contribute 45,056 whole-page bytes out of 509,086,792 native bytes. The large known common suffix instead has the same offset in the old and new complete *archives* on this edit. A pre-unlink descriptor, or a distinct previously retained complete archive supplied under the correct unit identity, is a possible origin for a copy-on-write writer. It would still need to prove the cloned bytes against the currently required archive contents and preserve ordinary fallback behavior.

Run `python3 -IB verify.py` and `sha256sum --quiet -c SHA256SUMS`. The extractor uses the full retained syscall forest, prior command JSON reports and target state from the companion historical and parser-operation experiments. Its first implementation classified all unit files by their basenames, which rejected the two mixed crates. Their per-unit and public rlib paths have the same basename but lie in different directories. The final extractor distinguishes the literal directories. It analyzed the same native commands. This package contains no timings.
