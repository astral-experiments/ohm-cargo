# Why a Ruff stdlib edit still rebuilds its consumers

Reversing Ruff commit `523d83c941cb` removes 323 bytes and 11 newlines before three public function declarations. A freshly compiled Rust caller through a facade reports all three definitions 11 lines earlier. Repeating the same behavioral edit while preserving the source positions keeps Ohm's stdlib public hash unchanged. The original whole-workspace edit ran 25 full compilers for build and 58 for test-build in both #232 and #233. [Workspace process counts, native products and Ruff diagnostic](https://github.com/astral-sh/ohm-cargo/tree/bf818ec9504eab29c29c9869e8216ee78d1d8ef8/benchmarks/ruff-dev-loop-20261027/stdlib-mutable-heldout-results)

There is a real failure mode for a shortcut that skips all frontend work. A small consumer's 51 direct codegen inputs remained equal when an upstream function became deprecated. Its 227 direct metadata inputs changed only for the upstream public hash and its own private hash. Rebinding those two values reproduced the fresh metadata bytes, but the current compiler emitted a new warning and a sibling using `#![deny(deprecated)]` failed. Reusing the entire compile would lose that error. Using unmodified stale metadata for a fresh Rust caller instead failed with E0460.

The archive contains fixture sources, the exact Ruff edit, producer item comparisons, wire offsets, ordinary caller diagnostics and compiler identities. The mixed-library control includes the preceding Cargo release and the intermediate release before its test-only fixture correction. Run `python3 -B verify.py` to validate the archive and reproduce the checks from its recorded output.
