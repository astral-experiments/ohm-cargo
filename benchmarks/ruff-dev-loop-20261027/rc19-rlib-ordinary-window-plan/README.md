# Time inside the selected Ruff archive on the ordinary compiler

This screen measures the interval enclosing creation and publication of the selected `ruff_linter` rlib during an ordinary unmodified `cargo +ohm build --locked --offline -j8 -p ruff_linter` command. It follows the loader experiment's cache-routing failure. Two machines use the official Linux Ohm 1.99.0-18, a private Btrfs volume, the original compiler and stock Wild. Use a copy-on-write snapshot of each machine's separately trained stock state at the same logical target and shared-build paths. Pass no compiler wrappers, environment injection, Rust flags, Cargo message flags or per-invocation Rust patch to the observed commands. [Stock baseline on Milan](https://github.com/astral-sh/ohm-cargo/tree/3fe561a2cc0c4dab54f20c2bd748d63d4c1dec04/benchmarks/ruff-dev-loop-20261027/rc19-rlib-package-stock-milan) · [Genoa controls](https://github.com/astral-sh/ohm-cargo/tree/6f633f4d30e27aad6106768e1cad0dc0ffb54f07/benchmarks/ruff-dev-loop-20261027/rc19-rlib-package-hloader-native)

On each machine start at Ruff commit `1e9287d7654f1dbe4943d67ed5ac5363c9ee2161`. Apply its complete reverse to get the content of parent `57d800be552a88751e7ecd06fc87b44714536033`, build and immediately repeat. Restore the commit, build and repeat. Perform this cycle three times, giving six real edits and six first unchanged commands per host. Save every attempted phase. The ten named Ruff libraries must rebuild on the edit and none on the repeat. A separately captured 248-unit typed roster identifies the current linter and AST inputs. Link the exact current libraries into the SIM222 consumer after each pair and check the respective line numbers. Use the already qualified independent empty build to verify the edited verdict on each machine.

An external unprivileged observer watches only the selected root's per-unit output directory with Linux inotify. The ordinary compiler creates a temporary directory with suffix `.temp-archive`, then renames the final archive into the watched directory. Require exactly one matching creation, publication and temporary-directory removal per edit, in that order, and zero of each on the unchanged command. A missing event, queue overflow, changed work or failed compiler/consumer rejects the observation. Other event names are counted separately. The observer records a monotonic timestamp before every unsuccessful nonblocking read and another after each successful read. These bracket event delivery. Save both ends of the creation and publication windows. Use the time from before the empty read preceding creation to after observing publication as the upper endpoint, and the interval between the other two ends as the lower endpoint. Report all bracket widths and observer CPU use. The replay includes a local controlled writer with a genuine rename.

For each machine report all six interval bounds in milliseconds, their medians, and the interval as a share of the observed full edit and edit-plus-repeat command times. An implementation confined to this output stage cannot save more than its elapsed interval in the same command if all other work is fixed. Filesystem and scheduling effects in subsequent commands can differ. These are component bounds on a stock workload. There is no candidate arm, speedup, or statistical product result. If even the median upper bound on either host is under 1% of the full loop, retire this root-only optimization for this fixture. A larger interval leaves the source-level candidate to be tested directly.
