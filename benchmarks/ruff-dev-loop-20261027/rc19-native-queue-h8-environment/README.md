# H8 release Cargo and scheduler controls

The original unprivileged user namespace mapped only UID and GID 1000 and presented both the filesystem root and its home parent as 65534. The settled release-mode runs here use a private mount namespace with both original ID maps, verified root ownership and actual unprivileged Cargo. Each run used the same pinned Ruff checkout and the ordinary no-run workspace test command on 32 available CPUs with eight Cargo jobs. Each arm independently readmitted 605 of 619 units when that ownership changed. Each of the next two commands reported 563 fresh units. One of those commands recorded every physical compiler/driver process. The third command sampled successful reads of six registry manifest proofs and the Git index proof. Independent recomputation against each selected source manifest, Cargo stamp, serialized payload, or actual Git index agreed in all 21 cases.

The default SDK is the released Linux x86_64 Ohm 1.99.0-18. The matched A/B pair shares Cargo source 235f9228651b74c591e6f62cae4c9b761448dd2d, with the scheduling tie-breaker at 4b0751af97bfa22204a013d0d1f0707382b0df52. Every arm ran one full ron compiler and 50 cached Rust drivers. The 50 GCC, 50 collect2 and 50 stock Wild children linked the same named targets. The native JSON keeps each successful executable's device, inode and original ordered-argv digest. RSS/PSS series are outside timing, in bytes except the single-child wait4 maximum in KiB. The process tree was sampled every 55 ms, and proportional sizes every 350 ms.

A repeat build of the unchanged baseline produced a different raw Cargo file. The nonallocated symbol/string tables and GNU build-ID descriptor differ. In the loadable segments the only additional change is byte 40 of the ELF header, pointing at the relocated section-header table. The section hashes, actual program headers and mapped-byte offsets are included. Release-SDK objcopy on diagnostic copies made the two entire baseline files byte-identical while preserving ordinary Cargo version and subcommand-list results. The proposed measurement uses the original unstripped A/B images. These native diagnostics contain no scored time or claimed scheduling improvement.
