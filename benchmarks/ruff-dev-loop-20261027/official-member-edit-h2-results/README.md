# `cargo build` through a real Ruff edit on the two published Linux SDKs

On the released Ohm 1.99.0-16 and -17 packages, the first unchanged `ty_wasm` build after editing Ruff fell from 1.384 s to 0.326 s. The edit plus that build fell from 4.290 s to 3.246 s. Both improved in all 24 direction-balanced pairs. The edited command alone had no measurable difference in this comparison.

| Ordinary `cargo build` in `crates/ty_wasm` | -16 median | -17 median | Paired reduction (95% interval) | -17 faster | Holm p |
| --- | ---: | ---: | ---: | ---: | ---: |
| Seven-line edit or restoration | 2.891 s | 2.883 s | −0.43% (−5.57% to +4.54%) | 11/24 | .871 |
| First unchanged build | 1.384 s | 0.326 s | 75.31% (72.82% to 77.60%) | 24/24 | .00000703 |
| Edit plus first unchanged build | 4.290 s | 3.246 s | 24.42% (20.68% to 28.01%) | 24/24 | .00000703 |

Both releases compiled `ty_vendored` and `ty_wasm` and ran one Wild link on the real edit and restoration. On the unchanged commands -16 repeated both compiles and the link. The -17 package kept all 304 Cargo units fresh and all five tracked native products untouched. All 62 independently linked Rust callers returned the entire original or edited `functools.pyi` exactly. The embedded typeshed ZIP and per-source product checks passed. The two SDKs produce different cdylib bytes across releases. Each release was compared to its own independently checked outputs.

The checkout was Ruff `93526150df`. We alternated the seven-line change from `1eab8c883a` and its restoration. Both releases used the same canonical unspaced SDK and source paths and the same target name containing a space. Each had an isolated, already-built target and shared build directory on the same tmpfs. Cargo used four jobs on CPUs 0–7. Each pair ran both releases in prospectively randomized order, balanced within each edit direction. Only `cargo +ohm build --locked --offline -j4` was timed. The immediate repeat followed its edited build with only a file-stat check in between. Native traces and product verification ran outside the clocks.

An independent source-matched comparison found a 6.16% slowdown on the edited build, a 76.61% improvement on the first unchanged build and a 22.46% improvement for the two commands together. That comparison isolated the corrected sources within the -17 release candidate. This study compares the full published -16 and -17 packages on a second host. The edited-build estimates differ between the comparisons. Both reproduced the saved compiles and link and the improvement across the two-command loop.
