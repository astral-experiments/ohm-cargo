# Prospective Cargo instruction and Ruff wall-time study

Measure the first dirty build of the 300-unit Ruff `ty_server` end-to-end target after the recorded historical parser edit. Both Cargo images must perform the same full compiles and native link, pass notebook tests, and produce an executable matching a clean build. `plan.json` records the original holdout rules and assigns the order of every pair. `source-enrollment-v1.json` and `builds.json` record the common symlink repair and the release-profile products. A directory-size observation motivated the experiment and contributes no observation to either measure.

The primary measure is Callgrind instructions in the root Cargo process. It excludes the child compiler and linker, which must still run and produce their registered outputs. The separate wall series uses ordinary, uninstrumented Cargo invocations. For each measure we report median paired log ratios, nonparametric 95% intervals from 30,000 paired resamples, and two-sided tests over the preassigned balanced orders (70 assignments for eight instruction pairs, 924 for 12 wall pairs). We also report median absolute paired differences and results by order. A performance PR requires a primary improvement with a wholly negative change interval and p < 0.05. A wall speedup requires its own evidence.

The benchmark source retains the historical package layout. Real and temporary native arguments are distinguished through process execution and file receipts. Both arms require qualified clean and restored results before measurement. Fresh targets and build stores are isolated per arm; storage checks apply to the actual build filesystem. Neither outcome had been measured at enrollment.
