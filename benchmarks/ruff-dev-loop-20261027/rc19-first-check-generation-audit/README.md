## Source and observed order

The compiler invocation for index has exactly the same full argument SHA-256 on each edit and first repeat. It opens through the same literal `--extern ruff_python_ast=…/libruff_python_ast-58057b12cc3f5bc9.rmeta` argument and writes the same check unit `-dcdcb0c9486a5ac5`. Cargo marks both AST and index built with their previous public hash on both edits. After observing the stale timestamp at the start of the next command, Cargo still recognizes index’s same hash but marks its inherited metadata changed. That state propagates through the 11 actually recompiled units. The sole second-repeat compiler is forced by a missing `ty_python_semantic-6b9874c016d55a10.d/ohm-foreign-span-bytes` sentinel. [Initial dependency comparison](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/fingerprint/mod.rs#L2280) · [Previous dependency generation](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/fingerprint/mod.rs#L642)

On a real worker’s successful completion, Cargo computes the maximum of the saved output time and the live Rust dependency times. For a check unit with one rmeta there is no other output to cover a newer dependency. It immediately writes the result with `set_file_mtime` when the local hash is unchanged and no metadata dependency is marked `BuiltChanged`. A dependency still `Pending` is accepted in that last decision. The headstart scheduler permits the consumer to finish before the producer and holds its output for presentation, while the worker-side fingerprint/mtime decision has already executed. The original two runs bound final timestamps and completion ordering but did not observe the exact mtime each worker read. A separate full-syscall reproduction in both directions reversed the completion order, retained equal AST/index output times, and did not reproduce this stale edge. [Restoration](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/fingerprint/mod.rs#L583) · [Published state update](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/fingerprint/mod.rs#L1199) · [Headstart settlement](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/job_queue/mod.rs#L857)

Treating a pending metadata producer as changed at this decision preserves the ordinary consumer output time and avoids an early claim about inherited metadata. This is a prospective guard. It can increase work when the producer later proves unchanged. Among the 47 workspace check units with an unambiguous retained public-hash sidecar and corresponding edit completion log, three literal dependency edges finished consumer-first on the reverse and five on restore. The four other compiler processes include three native dependency compilations and one proc macro. A producer could still finish with a newer final timestamp, so acceptance requires the actual post-edit clock, whole compiler roster and independent correctness controls. A settlement hook would have to defer or recompute provisional build-state decisions as well as times. Simply raising a path timestamp after a late changed/failed producer could mask invalid output. The focused upstream-error-recovery and transitive-trait-ambiguity tests cover important negative cases.
