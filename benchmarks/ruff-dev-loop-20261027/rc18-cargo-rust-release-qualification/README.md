# Ohm 1.99.0-18 Cargo and Rust release qualification

The tested Cargo and Rust changes are ready for the normal 1.99.0-18 release workflow once the manifest in #198 lands on protected `main`. The regressions reproduced on the published 1.99.0-17 toolchain pass on the candidate. This recommendation applies to Cargo `7181bfa6256f` and Rust `9828b82f475f`. Rust pins that exact Cargo. [Release manifest](https://github.com/astral-sh/ohm/pull/198) · [Cargo pin](https://github.com/astral-sh/ohm-cargo/pull/262) · [Rust pin](https://github.com/astral-sh/ohm-rust/pull/246)

| Case | Published 1.99.0-17 | Proposed 1.99.0-18 |
| --- | --- | --- |
| Six retained targets with edited file inputs | All six reported fresh and returned 17 | All six returned 29 on the first build after upgrading, matching independent clean builds |
| Two warm checks after an external metadata input changed | Both accepted invalid source | Both rejected it with the same E0308 diagnostic as a clean check |
| Valid incremental compilation after a dependency's public declaration moved | The compiler panicked in `module_children` | The next warm compile succeeded |
| macOS arm64 C-backed derive and attribute macros after a native-only edit | Both returned 17 twice. An empty target returned 29 for both | Both returned 29 on the first warm build and the repeat. Restoring the C source returned both to 17 |

The Cargo replays include a same-path toolchain upgrade with existing target state. The compiler replays include ordinary mixed rlib/cdylib builds and a separate producer built with the span-ignoring option. The native-macro comparison ran the published macOS archive and a stage-1 build of the candidate compiler source on the same arm64 runner. Linux additionally exercised release-profile rustc, rustdoc and Cargo.
