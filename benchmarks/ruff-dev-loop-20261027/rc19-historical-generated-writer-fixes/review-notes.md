# Historical Cargo cache writers

Each repair targets the open PR head that added its writer. The local qualification branches share the same atomic write primitive. Existing user-facing `write_atomic` callers retain their symlink-following contract. Generated-file callers explicitly replace the final directory entry. For existing regular destinations the no-follow primitive carries their ordinary permission bits across publication. This does not bind a parent-directory symlink or grant exclusive control over a build directory.

That Cargo had no automatic public-hash option. | Compile a library and executable with the historical supported compiler setting, change the public return type and result from 17 to 29, and run the binary after the edit and repeat. A separate real target omits the option. |

Clear only the successful unit fingerprint in the private target to force another genuine registry compile. Install the symlink immediately following the real IN_DELETE and verify the consumer prints the intended value. A symlink installed before compiling is cleared normally. |
| #147 | An eligible integration test is being checked, defaults and early-test scheduling are active, its own library participates, and rustc reports that the library is used. | Run genuine cargo check --test witness. Compare installing a symlink after IN_DELETE with preinstallation and defaults off. An unchanged repeat must be fully fresh. This check compiles the integration target. |

For #66, #75 and #147 the local qualification has a helper-only merge over the exact original and a separate writer commit. The site patch includes only the relevant writer and any checked-in local regression. The common helper applies once to the real stack. The #53 metadata prerequisite is distinct from the public-API-file change.
