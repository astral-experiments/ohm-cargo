# Cargo worktree marker symlink behavior on Linux

Published Ohm 1.99.0-18 replaced the contents of a pre-existing file when a worktree marker was a symlink to that file. The fixed Cargo replaces the marker itself. An ordinary crate running on the released Rust and Wild exercises five writes, covering the seed, untrusted-input deny, local proc-macro, saved build-script result and post-build-script dep-info deny paths. The first three writes each occurred during a build with all three artifacts fresh and zero compiler or build-script executions. The remaining two exercised an actual build-script rerun and a post-script dep-info write.

Each Cargo state runs eight ordinary builds. The released executable reproduced all five victim overwrites. Two independent builds of the fixed Cargo yielded the same complete 117,242,864-byte ELF, SHA-256 `a19d515cc301c05ad345ad0d657508905c28a2c900e01963632724cfd3b7289a`. Each run of the fixed binary preserved the victim bytes, inode and mode and replaced the symlink with the expected regular marker. The native receipts include syscall excerpts, the physical compiler/script census, each file’s original and final bytes, and hashes of stdout, stderr and the complete syscall log per command.

## Source and toolchains

The release Cargo base is `7caf39914da1e28a67744ecbc963a5f26361474d`. The final QA head is `235f9228651b74c591e6f62cae4c9b761448dd2d`. Its parent `6b5274b9363e0b4355d46418f78073ee0b4dfe46` contains the production correction and atomic-write tests. The head changes only the integration-test invocation to request a shared Cargo cache explicitly. The complete parent-release-to-final diff is included. All 3,108 tracked files and modes were verified against their Git objects before applying the patch. An independent projection checks all five changed files against the final commit.

The fixed Cargo was built under a locked, offline development profile with Ohm defaults compiled in, debuginfo 0 and incremental compilation disabled, using a private Linux Ohm 1.99.0-17 compiler. The two source-bound builds used 12 and 4 Cargo jobs and kept the same parent version stamp. Every marker and worktree runtime check used the x86_64 Linux 1.99.0-18 Rust toolchain. The release archive SHA-256 is `629abab6a87c84bb4d910549ca96a31e437e3dc9de3039fedcbb7b50d198a5e8`. The original Wild, Cargo, driver, frontend and rustdoc digests are in `build/official.json`. The outer installer controller reached its 150-second timeout. The installed alias and version marker, installer completion text, package archive and toolchain bytes were independently checked before any test.

## Committed regression and independent controls

The final checked-in integration test succeeded against the fixed Cargo and failed against the released Cargo at the victim-content assertion. The release replaced the bytes of `original` with a 64-digit lowercase hexadecimal build-script result followed by a newline. The same test harness was used in both arms, with successful execs of each bound Cargo captured by strace. Two nearby worktree tests also passed against the fixed Cargo. Three cargo-util unit tests exercised ordinary writes, permissions and traditional symlink-following alongside the new marker behavior.

The first test patch omitted a test-only import, producing E0425 while compiling cargo-util tests. The initial integration setup ran beneath a path with a `target` component, where Cargo disables automatic shared-cache enrollment. Before the explicit flag was added, neither the new regression nor the existing import test found a namespace. In a separate neutral path the unchanged existing import test saw one genuine namespace against both binaries. It then failed at the identical line in its helper. The helper expects the refusal text “without copy-on-write support”, while both Cargo binaries reported a skipped unsupported or unprepared profile. The normalized stderr was the same.

A separate ordinary non-symlink fixture created two worktrees per Cargo on the same filesystem. The kernel rejected reflinks with EOPNOTSUPP. Both Cargo binaries reported no snapshot imported, built each worktree once, and found the next build fresh. The resulting programs printed `repro-29` in all eight invocations. This machine provides no affirmative coverage of imports on a reflink-capable filesystem.

Run `sha256sum -c SHA256SUMS` and `python3 -IB verify.py`. The three ordinary native fixture JSON files are exact stdout from the same included reproducer. To rerun against an installed x86_64 Linux release, supply its SDK, the absolute Cargo path, its SHA-256 and CPU IDs allowed by the host to `reproduce.py --sdk SDK --cargo CARGO --cargo-sha SHA --expect protected --cpus CPU_IDS`. Use `--expect vulnerable` for the released Cargo. The fixture requires Git, rustup with its Cargo proxy, bubblewrap and strace.
