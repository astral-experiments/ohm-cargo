# Replay of parsed procedural-macro inputs on the Ruff parser

The extra work to restore parsed source files and syntax contexts stayed within the registered 3% instruction margin on both compiler histories. The two upper bounds were +0.047% with retained parser state and +0.035% with empty parser state. The 12 paired observations per endpoint used the native compiler invocation captured from an ordinary Ruff workspace build after the same historical parser edit. Positive paired changes indicate additional instructions. The median of paired log ratios compares adjacent parent and candidate runs; it can differ from the ratio of the two arm medians. Each bound is the tenth ascending paired ratio of twelve, giving at least 98.07% one-sided coverage per history and 96.14% across both histories under the registered paired sign model.

All 48 rustc processes exited successfully. Their 3,984 threads each supplied a start and final count. Every process mapped the pinned rustc frontend, intended compiler driver, real get-size derive library, DynamoRIO runtime and counter. Every invocation reproduced the ordinary compiler's stdout, artifact messages, separately emitted and archived Rust metadata, ordered native object payloads, GNU symbol-to-member associations and normalized archive member directory. Each raw archive digest is retained. The code-generation object filenames include a rustc per-invocation suffix, also present in the archived list of object names. The stored normalization changes only that suffix in both locations and checks each association.

The metric counts application basic-block instructions in the resolved compiler, including native code generation. It excludes Cargo scheduling, rustup and operating-system work. The preceding 32-pair native wall-time experiment established its warm margin and did not establish its empty margin. A separate same-image experiment measured a +3.98% wall-time difference between two copies of the identical compiler.
