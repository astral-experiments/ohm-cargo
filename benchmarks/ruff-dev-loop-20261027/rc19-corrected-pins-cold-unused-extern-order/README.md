# Cold speculative integration tests

One ordinary, initially empty two-test build of the historical Ruff parser edit executed two full `fixtures` compilers with identical 386-element argv. Two distinct stock Wild processes targeted the same canonical executable. Cargo emitted one `compiler-artifact` row. The 196 linker arguments changed at both GCC/rustc temporary paths and 42 Rust object names. The raw intermediate executable and its event ordering were not captured in this run.

A separately empty ordinary Cargo build attached an unprivileged native observer to the actual compiler and file descriptor writes. It observed one full compile per integration target. Each compiler had already written its real unused-extern report before invoking GCC, collect2 and Wild. `fixtures` used its own package library and listed 557 tests. `generate_inline_tests` reported the package library unused and listed one test. Each complete ELF was copied from a held descriptor before the compiler was reaped. The compiler and stock-Wild binaries in this run match the primary parser receipt. The synthetic child validates the observer event sequence. Timing was outside this diagnosis.

Cargo already considers a qualified prior `CheckHint`, the prior native unused-extern manifest and the producer completion observed at dispatch. A previously unseen integration target can report actual use only after compilation has started. Cargo currently discards a speculative used-self result after the child finishes and then spawns a full retry. Its command reader handles callback errors after child output processing. Early cancellation would require separately proving the first used-self signal, reaping native jobs, and preserving cancellation, errors and publication semantics. The evidence here does not pair the two-compiler case with a retained first ELF or a genuine doubly linked signal ordering. No avoided link or wall-time claim follows.
