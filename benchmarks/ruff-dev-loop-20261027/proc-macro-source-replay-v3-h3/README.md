# Native procedural macro source and syntax-context replay

Reusing an otherwise valid procedural macro expansion could change a native program or make a downstream Rust library incompatible with a source-identical producer. String parsing creates virtual source files in the compiler. Starting a procedural macro server also interns its definition-site, call-site and mixed-site syntax contexts. Later macro invocations can observe both global effects. The corrected compiler restores the server contexts before cached token decoding. It saves parsed source strings in expansion order and restores them when the matching cached query actually supplies its result. A rejected cached expansion executes the current macro. ## Ruff workspace

Ruff’s genuine three-file historical parser edit built with its normal 501-unit workspace graph. The original repeat was 501/501 fresh. Restoring or replacing just the parser’s incremental state kept all 16 actual direct externs and the procedural macro binary identical. Both edited builds produced the same native Ruff CLI diagnostic, private crate hash, public hash and stable crate ID. All four newly constructed ordinary Rust callers ran successfully, including both crossed library combinations. Each caller’s traced file opens and mappings identify the exact chosen parser and bridge archive.

The separate full-library reuse experiment still fails its strict cross-history raw metadata gate. Two further ordinary builds reproduced each history exactly, for the separately emitted file and the ELF metadata member inside its archive. Four compiler-only diagnostic replays, including the two with `-Zmeta-stats`, matched the real outputs byte for byte. Of the 30 measured sections, the empty parser state used 2 fewer bytes for MIR and 72 fewer bytes for the constant allocation index. The hygiene and definition sections have equal sizes. No timing is reported here.

Two inline Rust functions returning the same literal reproduce the allocation-index effect without any macros, Cargo registry or external crate. Changing just one result from 7 to 8 produced a 52-byte empty-versus-retained difference in the allocation index on both compilers, with or without Ohm’s experimental metadata flags. Every native caller in that comparison printed 8.
