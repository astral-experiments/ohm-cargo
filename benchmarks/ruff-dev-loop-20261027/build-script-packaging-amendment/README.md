# Prescoring amendment for reproducible Cargo executables

The original 24 paired episodes, source, randomized order, estimands, admission gates and analysis remain in the registered timing plan. This amendment specifies the final packaging recipe before a third independent release-build cohort or any timed Ruff command. [Timing plan](https://github.com/astral-sh/ohm-cargo/tree/30c4bfb6a1989da3818a2381b6cd46cd39c0e50e/benchmarks/ruff-dev-loop-20261027/build-script-timestamp-timing-plan).

Two preliminary PGO builds failed the whole-executable A/A SHA-256 gate. The sequential baseline returned 6746a462… and 3a2efc58…; the independent-seed baseline returned 5553c6b8… and ab6527de…. Their raw binaries will remain excluded from timing. In the second pair the only differing sections were .strtab, .symtab and .note.gnu.build-id. Both entire 25,283,718-byte .text sections have the same SHA-256, 84fe9ef8dc9b07b4ea1bf76562b569d2609f2ec1e328b9af763b07e86b193c28. A GNU objcopy trial removed PT_GNU_RELRO and changed PT_GNU_STACK alignment. It was rejected.

A pilot using the frozen Ohm distribution's own LLVM 23.1.1-rust-1.99.0-beta `rust-objcopy --strip-all --remove-section=.note.gnu.build-id` preserved all 14 program headers, every retained allocated section including .text, .rodata, relocation bytes, symbol/version tables and dependencies. Pilot baseline images independently package to 060c035c… and candidate to 033852e4…. The executable tool SHA-256 is 4d8b37053002ebfea8b6cf11e13d2a42ced0d93e8db2803f7d01c0813dcb8ab0 and the SDK libLLVM SHA-256 is 43bac9749e539cd5988a4d5452b64582cf07ac9e7c059fde29c7bee76e106c51. The full per-image reports list the actual program headers, loaded-segment hashes, and every changed mapped byte offset. Only ELF section-table bookkeeping and the removed build-ID note may differ. Section indices recorded by readelf --version-info shift with removal of the preceding note, and their target names and their complete on-disk version records are compared. The other two notes remain intact.

A new A/B/A build will compile the Cargo library and binary from scratch for each arm, with a separately copied immutable, hashed common registry, sysroot and target-dependency snapshot bound to identical canonical paths. Both 3,107-blob source manifests and the profdata are bound by the builder. All three new raw executables are preserved; their final experimental images use the same LLVM packaging and gates as this pilot. Two complete packaged parent executables must match, byte for byte. Each immutable raw/packaged pair must retain all dynamic dependencies, all program headers including RELRO/STACK, every other allocated section, and all PT_LOAD bytes aside from the exact header/note offsets above. Both ordinary Cargo version responses must match. The raw pair and the packaged pair will also run the identical real Ruff workspace script edit in both directions in unscored native calibration. Their launch rosters, freshness and script/metadata results must agree before release. Both stage-2 release controls use the same fixed Ruff compiler.

This benchmark will use symbols-stripped, build-ID-free Cargo binaries constructed with the release Rust PGO training data and SDK LLVM tool. It does not identify the packaged bytes with an unmodified distributed Cargo executable. Production claims will be limited to the same source changes in the stated release-style packaging. Final exact image and runner bindings must be published before scoring. A result that fails a loader or behavior gate remains ineligible.
