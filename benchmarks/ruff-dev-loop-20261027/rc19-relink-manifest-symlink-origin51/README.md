# Original Cargo PR #51 follows symlinks while writing relink manifests

The original head caac2566f0 and its direct parent 30004d93bd were built from their real Git sources. All 66 compiler runtime files used for these controls match members of the official ohm-1.98.1-1 Linux archive. The fixture is a normal two-package Rust workspace. It printed 17 cold, 18 and 19 after two ordinary application edits, 31 after a library implementation edit, 31 on a fresh repeat, and 17 upon restoration. An extra application edit printed 20 in the dangling-link history. Each sentinel and every link lived in a separate ordinary-user-owned directory. The compiler was unwrapped throughout. The first independent six-command history also ran without syscall tracing.

At the original head, the historical CLI accepted `-Zrelink-only` and rejected `-Zrelink-only=yes`. The positive arm explicitly supplied rustc's `-Zpublic-api-hash` through an isolated Cargo command-line config. A full binary compilation removed the prior manifest. After observing its exact IN_DELETE event, a same-user watcher placed a symlink at that filename to an arbitrary private sentinel. Cargo successfully linked the edited application, then renamed a file containing a version-3 relink record over the unrelated sentinel. An existing arbitrary-content sentinel symlink installed before a full compile was removed by the normal invalidation and remained intact.

On a dependency-only edit there was also a distinct overwrite without a race. The cache-name symlink already pointed at an independent valid copy of the prior manifest with an ignored JSON note. The producer recompiled, the application reused its cached objects, and normal GCC/collect2/lld linked an application which returned 31. Cargo replaced the target manifest, erasing its unrelated JSON note. In a third original-head control the cache-name symlink initially pointed at an absent destination. The full-compile invalidator tested exists() and left the dangling link in place. The writer created a v3 manifest at the new destination.

The original head with only the public hash or only the Cargo relink switch created no relink record and left the sentinel alone. The direct parent produced the correct program on both ordinary and public-hash-only histories and never wrote the record-shaped entry. Its rejected historical switch was retained as a separate parser control. The old compiler invoked its bundled rust-lld. Thirty-eight kernel-traced commands plus six untraced commands verify both writer paths. The original before/after bytes, file identities, normal Cargo stdout and stderr, raw trace hashes and successful filesystem rename calls are bound individually.
