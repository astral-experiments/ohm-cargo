The times include `strace` and Cargo fingerprint logging. Every first unchanged run reported the expected missing `ron-…d/ohm-foreign-span-bytes` prerequisite. The one full compiler invocation was `ron`. Its `.d` listed 0 checksums on the empty target and 45 on the first full-workspace repeat. Its Rust metadata, native archive and encoded Cargo dependencies changed. Its Cargo fingerprint JSON and public hash stayed identical. All 619 whole-workspace artifacts were fresh on the second repeat, with no rustc or native linker processes.

Both trust histories had the same single raw ELF change among 110 products. The `ty_python_semantic` test's 178,680,456-byte file differed in 33 bytes. The 32-byte GNU build ID differed and its `.rodata` section header's `sh_entsize` changed from 8 to 0. The two complete binaries had identical bytes outside those fields. The default-history cold output had already been replaced when supplementary physical files were copied. The independent opt-in history retained the full raw files matching both of its SHA-256 values. `native-one.json` records the byte positions and both full-file and field comparisons. This resolves the executable difference separately from the genuinely different `ron` Rust archive and metadata.

The original default-trust cold Cargo command succeeded. Its after-command classifier stopped on one GNU `ld` invocation without an explicit `-o`. The corrected auditor recognizes that system link’s implicit `a.out` and counts it separately from bundled Wild. One resume failed before invoking Cargo because its new script path was outside the sealed namespace. The subsequent resume mounted the corrected auditor read-only at the original registered path, validated the preserved cold command and collected the two originally scheduled repeats. No cold run was substituted. Candidate timings are outside this diagnostic.
