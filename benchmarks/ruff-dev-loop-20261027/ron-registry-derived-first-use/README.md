# A native registry derive can remain stale on the first genuine foreign-span observation

The Linux 1.99.0-17 release returned a native program printing `17/29` after a declared build-script input and one Rust source line changed. An independent empty build printed `29/29`. Both numbers come from the same registry proc-macro DSO. The first is baked by `#[derive(Native)]`. The second is returned by a new two-token join using an imported macro. The cache reused the derive from an earlier source state which had never made that observation. The old and new DSOs have identical `.rustc` and `.dynsym` bytes and different `.text` bytes.

The Cargo-managed graph uses three registry crates, two of which are reexported by the third. Every Rust and C job, its arguments, package checksums, full/native indicators, and compile-time derive calls are retained. `native.c` is generated by the registry macro's normal build script, which prints `cargo:rerun-if-env-changed=MANAGED_OBJECT_SOURCE`. The natural case changes its value from `17` to `29`. Cargo invokes the C compiler, links `choice.o` into a new proc macro, and recompiles the Rust caller. These ordinary commands use no wrapper, external `--extern`, timestamp intervention or external DSO store. A separate synchronized case tests replacement of a genuinely mapped old DSO under a preserved timestamp. Its results matched the natural case.

| Cargo/compiler | First new observation | Two further builds | Independent empty |
| --- | --- | --- | --- |
| Shipped -17 | 17/29 | 29/29, 29/29 | 29/29 |
| #261 | 17/29 | 17/29, 17/29 | 29/29 |
| Four-line known-observer correction V1 | 17/29 | 29/29, 29/29 | 29/29 |
| Shipped -17 plus explicit cache opt-out | 29/29 | 29/29, 29/29 | 29/29 |
| #261 plus conservative default V2 | 29/29 | 29/29, 29/29 | 29/29 |

V2 removes automatic `-Zcache-proc-macros` from the Ohm compiler option vector, leaving explicit opt-in available. Rust's default for that option is false. Under #261, V1 and V2 the two observer repeats were full compiler invocations. On original -17 and its explicit off control, the second repeat was entirely fresh. This evidence assesses correctness and makes no claim about elapsed time or the performance cost of removing automatic macro caching.

Two independent retained-target migrations reproduced the native error with the actual released Cargo and separately with #261. The Cargo path, compiler, project source and target/shared directories were held fixed while the resolved Cargo binary was switched. Upgrading to V2 immediately returned 29/29, as did the next build, the downgrade and re-upgrade, and the independent empty control. The found unit depfile and observer record were bound to the actual Rust compiler `--out-dir`; the physical Cargo hash is recorded for every transition.
