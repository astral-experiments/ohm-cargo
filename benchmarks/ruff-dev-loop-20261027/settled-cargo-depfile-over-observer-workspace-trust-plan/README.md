# H8 native cache-directory trust amendment

The first native #261 workspace qualification stopped at the assertion requiring a nonempty Git verification store. Its task parent directory was mode 0775; its Cargo home was 0700. The same-owner parent on the previous eligible host fixture is 0700. Cargo's shared path validation rejects a writable ancestor and skips both the Git index and registry manifest proof stores. Neither proof directory existed in the first H8 fixture. This was detected after the normal 501-unit zero-rustc trace of the parent and before any H8 count. The cold build did compile 501 units, the historical edit affected 12, and the three true observer fixtures were independently eligible. The rejected physical state, ordinary command output and all old data remain intact.

Only the dedicated outer directory mode is tightened. All source, runtime, target, shared and Cargo home paths are preserved. Eligibility now explicitly validates pre-repair physical identities, all 922 pre/post product bytes, 58 depfile bytes, the unchanged physical Git index, and new native verification of both stores. The ordinary runs must be completely fresh throughout; the only permitted timestamp changes are the two previously registered wasm library depfiles. The two measured Cargo binaries must actually open both caches, leaving their inventories byte-identical. The original worker then performs its complete two-arm qualification in a fresh results directory. No countdown or scoring release is included in this amendment.
