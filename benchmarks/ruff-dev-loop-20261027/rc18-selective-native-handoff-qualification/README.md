## Native interface

The transport accepts a unique final `-o` naming the single exact enrolled file. It verifies its own policy, the checker, GCC and collect2, and checks the extant file’s type, ownership, permissions, link count, xattrs and stable identity. It acquires the real jobserver budget and requests the trained result for that width. Explicit linker threading, response files, unsupported privilege/architecture and native debugger/loader overrides trigger the ordinary link. Other output names execute stock Wild immediately with the original arguments, argv[0] and environment.

The checker reads a sealed memfd through standard input. The JSON contains the original arguments as hex, the current directory, SHA-256 of the sorted raw environment, actual GCC and collect2 digests, worker count, training digest and a random nonce. On success the response binds the exact request bytes, training proof, worker count and BLAKE3 of the executable. Nonzero status, diagnostics, malformed replies, mismatched digests, timeouts, changed file identity and unreadable audit state all use stock Wild. An affirmative result leaves the output file in place. The enclosing GCC process still handles its own post-link hook and can fail independently.
