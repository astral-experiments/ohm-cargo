# Native rustc metadata reuse after the Ruff stdlib edit

The real 523d83c941cbae9b7c8a10739c839a8eeda3245d reversal on Ruff 93526150df078af7dd8fc4226cdcc469539d2001 moved three later public declarations by 11 lines. Independent native callers saw the diagnostic positions change. The existing full-workspace study ran 25 full build compilers and 58 test-build compilers with both #232 and #233. [Workspace rosters and behavior](https://github.com/astral-sh/ohm-cargo/tree/bf818ec9504eab29c29c9869e8216ee78d1d8ef8/benchmarks/ruff-dev-loop-20261027/stdlib-mutable-heldout-results)

The exploratory compiler retains the ordinary frontend, diagnostics, code generation and link requests. A hashed incremental manifest records the owning crates of foreign references serialized into an ordinary native rlib. On an existing metadata-prefix hit it can rewrite an unreferenced dependency's 16-byte expected public SVH at a typed dependency-table offset. Crate identity and number order, all other dependency fields, the existing metadata digest and source-file layouts, protected text, local definition index order and exact spans must still agree. New source deprecations still warn or cause a build error under deny(deprecated).

Six direct workspace consumers were screened against known definition hashes and earlier completed query graphs. Only ty_ide and ty_python_semantic had neither a matching physical DefPathHash in the metadata nor a per-definition direct dependency of the Metadata task on the changed library. For those two we replayed actual ordinary native rustc commands captured from the 362-unit Ruff closure, with the original project's source, flags and upstream rlibs. The Rust source part of the historical reverse patch was applied at its original absolute path. The Markdown part has independently been verified to cause no compiler invocation. Only the six necessary crates' output and incremental directories were writable, always from private copies. The stage-one driver is 7d5062b08021e29073bc06eee54a775ef02f299418e57d0a9565175134fde6fb. Its underlying mixed-library stage is b5fb832c on top of #233. The ordinary rlib invocations did not request that separate mixed-library optimization.

For ty_python_semantic, only the local crate_hash input changed among 953,893 direct previous Metadata inputs. The 149 physical source layouts and 43,904 protected text ranges also agreed. All individual declaration and identifier spans matched when keyed by stable DefPathHash, but 133 of 89,246 positional local DefIndex entries moved. Its manifest contained 188 crates and a single changed public SVH, for a crate with no recorded foreign positional reference. The definition-order guard rejected the reuse. Its forced and natural branches performed full encodes and emitted identical metadata.

ty_ide kept all 7,494 DefIndex slots, 44 source layouts and 5,609 protected spans in order. Both branches began with the same physical incremental checkpoint after the changed dependency chain had been recompiled. Removing the typed prefix manifest from one restored copy forced the ordinary encoder. It was the only intervention under test. The initial unscored pilot took 1.146 vs 1.253 seconds. A separate predeclared child-only cohort restored the same checkpoint before every command, with 12 independently ordered pairs balanced six each way. The single endpoint was the whole rustc process, including frontend and codegen. Restoring the snapshot and checking output digests were outside its timer.

The geometric mean reduction in child time was 9.56%, with a paired 95% percentile bootstrap interval of −3.65% to +21.14%. Eight of twelve pairs favored reuse. Medians were 1.369 s with reuse and 1.430 s with full encoding. The two-sided exact balanced-order p-value was 0.09957 from 924 assignments. This cohort was inconclusive. Full-workspace performance remains unmeasured.

All 24 children succeeded. Within every pair the metadata bytes and all 171 native object contents matched. The 173-member archives themselves differed. Directly decoding the two initial 11,302-byte .rmeta-link tables found the same object order after removing incremental session suffixes from filenames, no bundled native libraries, and the same set of referenced filenames as the actual object members in each archive. The other archive members' bytes matched. A genuinely fresh external native reader using both ty_ide and Ruff stdlib produced a byte-identical 170,598,376-byte ELF and ran with the expected changed results for ChainMap and WeakSet. The independent tiny negative controls cover exported inline code, constant values, a native static, a public layout and a forwarded foreign type.

A separately rebuilt stage-one control and candidate agreed on both crate hashes, all 188 bindings and metadata length for ty_python_semantic, but differed in 8,990 bytes in 1,309 runs. Within each driver the unchanged-source repeat was exact. All timing treatment and reference commands used precisely the same experimental driver and physical checkpoint. This experiment ran the compiler's normal frontend and codegen. It skipped no rustc process or link. The other 18 transitive build processes were not priced. The raw ordered command strings and environment from live traces are omitted. Traced argument identities and source-file digests are retained.
