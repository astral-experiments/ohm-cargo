# Dependency collection for cached relinking on a real Ruff parser edit

The three dirty jobs in the historical Ruff parser edit collected 68 dependency indices. Building those sets consumed **35,825 of 302,352,530 instructions in the Cargo process (0.01185%)**. Restoring the edit consumed 34,871 of 302,223,501 instructions (0.01154%). All four fully fresh observations performed zero collections. The registered threshold to take this change to a source-matched performance trial was 0.1% for the default edit.

## Source scope

Cargo creates the work closure only when the initial fingerprint marks the unit dirty. Rustdoc, reused test checks, run-script jobs and ordinary fresh jobs take different paths. A dirty unit that Cargo later skips can still incur this preparation. The code only consults the collected set inside the `reuse_codegen` short circuit. Default Cargo disables reuse after #282 while collecting other relink artifacts for scheduling. Explicit `-Zrelink-only=yes` can consume the set. [Job selection](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/compiler/mod.rs#L431-L462) · [Collection](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/compiler/mod.rs#L1123-L1150) · [Consumer](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/compiler/mod.rs#L1469-L1494) · [Option defaults](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/workspace/features.rs#L1384-L1392)

The dependency slice borrows the finalized in-memory unit graph. The filter first requires Build mode, a regular dependency and a library target. For a library, `rustc_crate_types()` clones its `Vec<CrateType>`. The existing code accepts only `Lib` or `Rlib` and looks up the dependency in the index created from the same graph’s sorted keys. Ruff’s parser had 16 direct build/lib edges, and both selected test units had 26. The actual graph recorded one `lib` crate type on each. All 68 vector clones, index lookups and insert calls were observed. [Graph indexing](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/ops/cargo_compile/mod.rs#L789-L794) · [Crate types](https://github.com/astral-sh/ohm-cargo/blob/8dc33c9cc641e2b641c5b8e7075652a3e9e1f70b/src/workspace/manifest.rs#L295-L305)

A narrow source guard could pass an empty dependency slice to the existing collection when `reuse_codegen` is false. With reuse enabled the original filter and index lookups would remain in effect. The collection has no filesystem or process access and supplies no rustc arguments. The measured fraction on this edit did not justify building a product arm. The result covers one 147-artifact command and directly attributes parent Cargo instructions. It does not estimate native elapsed time or a 619-unit workspace build.

Thirteen trees contained only evidence, 15 code trees predated the collection, and the remaining 269 constructed it unconditionally. The new gated consumer was present on #282, #283 and #284. #264 borrows dependency arrays while recursively scheduling and fingerprinting units. ## Native and counter controls

The study used release-PGO Cargo `8c1717fa…` from #284, the released Linux -18 compiler and standard library, and shipped Wild `0d633580…`. Two separate targets and build directories used the same Ruff source and frozen 498-package registry. Each independently compiled all 147 artifacts and settled with all 147 fresh. The source change reverses the nine-line parser fix and its two associated fixtures on Ruff `93526150…`. [Historical source](https://github.com/astral-sh/ruff/commit/a50dc58628691ee00a21809e19bdea71958e4f3c)

The ordinary command was `cargo +ohm test --locked --offline --no-run -j4 -p ruff_python_parser --test generate_inline_tests --test fixtures`. The explicit control supplied `-Zrelink-only=yes` as a Cargo option. An independent native trace confirmed that default ran three full rustcs and two stock linkers on edit and restoration. Explicit reuse ran one full parser rustc, two link-only rustcs, and two stock linkers in both directions. Four native repeats ran zero compiler and linker jobs. Both test executables matched byte-for-byte across modes within each source state. Both modes reported 558, 557, then 558 parser fixtures, plus the generator test. The independent caller rejected `from x import (*)`, then accepted it after reversal, and rejected it on restoration.

The counter includes the unit’s graph lookup, every instruction executed by the collection and its callees (including allocation and immediate destruction of temporary vectors), and transfer of the resulting set. The later final deallocation of the completed set is outside this region, at most one per nonempty job. The linked machine code has a unique fold call at `0x116d9b7` targeting `0xf93d60`. All addresses are specific to the authenticated Cargo ELF. The PID-checked DynamoRIO client counted all Cargo threads. Its 4,000,000-instruction positive calibration differed by 60 instructions. Assigning 32,000,000 additional instructions to eight separately executed workers changed the three-thread parent count by −79. The host refused the hardware `instructions:u` event; no Cachegrind engine was found in its retained software-counter bundle.

The first `cargo worktree` setup refused an existing empty target. A second setup admitted the same inputs with the required unused target path. The initial observer accepted the truly fresh controls but rejected its first dirty denominator because DynamoRIO delivered inherited thread-exit callbacks at multithreaded fork. Cargo itself returned zero, and its retained native executable passed. The corrected kernel-PID accounting used a separately restored history and preserved the original invalid denominator and native artifacts.
