# An accepted V8 reuse can leave the wrong ELF dependency

A small Linux fixture links an executable against a byte-identical DSO twice, after renaming the DSO from `helper.0123456789abcdef.aaaaaaa.rcgu.o` to `helper.0123456789abcdef.bbbbbbb.rcgu.o`. The DSO deliberately has no DT_SONAME. Wild therefore uses the actual input spelling as a DT_NEEDED entry. Stock Wild links successfully and the executable returns 42 both before and after the rename. V8 records two cache hits after the rename, leaves the old DT_NEEDED in the output, and the program fails in the dynamic loader with status 127 on both attempts. The old path had been removed by the rename. This is a synthetic supported invocation; the preserved Ruff archive measurements below are separate.

The host used a fresh private directory, a single allowed CPU, an ordinary user with zero effective capabilities, the packaged V8 `c813de15` and released Wild `0d633580`. All six real links returned 0. Stock's changed executable hashes to `d065cd6dfc4dfadfc8a5009419a9e13c016e2c002a9431776be8768cb2645022`; both V8 hits retain `aef9529a403d3a23e6a364cebe7f215cd27808beeaedd1630c827caf8eeea3b6`. The two DSO spellings contain the same SHA-256 `ac366815a3e6d87b4a573d1095c87656a0893f16849363f25b3432f2aa36970e`.

## Existing-output behavior

On those two real cache hits, tracing the output fd observed a read-only mapping and utimensat. On the genuine stock links, it observed ftruncate, a writable MAP_SHARED mapping, and fchmod. The measured binary was produced from c7eda769 and patch 6919b2d2. Its refresh_existing checks the open file's mode, device/inode, link count and digest before calling set_modified. It never wrote even one unchanged data byte on the hit. A subsequent unbuilt local working diff replaces set_modified with same-length ftruncate and make_executable. That diff also has no pwrite. The prior capability file check already demonstrates V8 retaining security.capability while the true stock link clears it despite identical output bytes. No capabilities were granted and that earlier setup was not rerun in this audit.

A separate ordinary-user surrogate used files owned by the running user. Starting at mode 04755, an unchanged-byte pwrite at offset zero and same-size ftruncate each yielded mode 0755 and identical data and inode. An ordinary timestamp update left mode 04755. The mode result alone cannot certify file-capability, ACL, fs-verity or other filesystem behavior for a future hit. The DSO wrong answer persists independently of output-fd metadata handling.

## Real Pydantic archive cost

V7's predeclared genuine Pydantic whole-build miss was 2.04% slower with a 95% overhead interval of 0.16–3.83%. The four cached-eligible GNU links missed in the qualifying traces, and both arms performed five real links and twelve full compiles. That baseline remains binding. [Genuine-miss context](https://github.com/astral-sh/ohm-cargo/blob/c977719f4247463537f6b9f978a5ce24fd4cda91/benchmarks/ruff-dev-loop-20261027/wild-reuse/wild-v7-plan.json)

The private archive snapshots from the same complete historical patch (SHA-256 `467330a56398032bfaed34cca5a89ed7de1a6459ddb95756180b16de69b912b1`) allow a small read-only test. The independent snapshots used Clang to invoke Wild. GNU ar member headers plus the GNU long-name table required 35,576 bytes per archive. This is the number requested by the reader; random touched pages, parsing time and cache traffic were not measured. Each Ruff producer had 256 native object members in the same canonical slots.

| Historical edit and mode | Archive size, original → changed | Changed native member lengths |
| --- | ---: | --- |
| Pydantic, default build | 242,514,522 → 242,514,506 | 2 of 256, decreases of 160 and 80 bytes |
| Pydantic, test build | 243,800,088 → 243,800,072 | 2 of 256, decreases of 80 and 168 bytes |

Comparing overall file lengths alone would discard the third case, whose different raw size came entirely from the excluded Rust metadata. A stronger early rejection could compare captured native member lengths against the actual currently mapped archive when its size differs. A changed vector can immediately choose the ordinary full link. An equal vector conveys no proof of reuse and must proceed through the complete verifier. The probe reads cheap structural inputs before the existing BLAKE3 pass over every mapped archive and the output witness; a later full scan for the same failed invocation would pay those costs again. Four of the five Clang build-phase Wild calls used a response file whose contents were not preserved. This packet does not establish exact per-link byte savings on all four original GCC misses, the cost of retraining after a miss or a wall-time reduction.

## Earlier library selection and archive names

V8 asks Wild's real FileLoader to resolve inputs before it considers reuse. A missing earlier search candidate is therefore reconsidered by Wild on every link. In the previous release-native controls the earlier `-L` archive changed the program from 42 to 21, a formerly unchosen archive member gaining a symbol changed it from 42 to 17, and both cases did real links. Thin external archive and filename-dependent SECTIONS scripts bypassed the shortcut, as did an active LTO plugin. The accepted simple INPUT/GROUP/AS_NEEDED case includes recursively loaded script bytes and selected operands. Those facts distinguish it from the rejected Cargo witness that remembered only old positives and missed a newly available nested script operand or earlier libgcc_s.so. A future gate must retain new native search and resolution on every admitted attempt.

The current GNU rlib projection includes member order, size and all native object bytes. It binds ordered symbol names to member ordinals and conservatively inspects the two ELF metadata wrapper shapes before omitting their SHF_EXCLUDE payloads. Its full-byte digest fallback covers unrecognized archives. The separate path_key and cgu_name functions strip a seven-character invocation suffix from names that *look* like Rust CGUs, both in argv and loaded filenames. They do so before proving an ET_REL object's name cannot escape. The fixture passes an actual ELF shared library through that rule. A genuine previous output proof would have to retain exact names for DSOs and other filename-consuming cases, including every source of a dynamic dependency name, and keep absence of unsupported script/auxiliary effects. Object-length matching or a cached archive member set cannot certify a hit.

Retain V7 and V8 as rejected. The length witness is grounded enough to test as a negative-only filter if a later positive proof is independently repaired; it supplies no performance measurement or fix for either independent V8 correctness failure. No product source, Ruff checkout, PR, release or reservation was changed.

## Reproduce

Run `python3 -IB verify.py` to replay the assertions against the bounded traces and preserved prior controls. On the dedicated host with the original pinned tools at the paths in ordinary_probe.py, run `python3 -IB ordinary_probe.py` as an unprivileged user to recreate the synthetic native controls. Run `python3 -IB header_probe.py /path/to/ohm-ruff-skip-links-20261027` for the three actual ar pairs using the original published-source campaign captures. The snapshots' SHA-256 identifiers and typed process counts are retained in archive-headers.json; this package omits those large object files.
