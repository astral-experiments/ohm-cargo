# An excluded ordinary-worktree build-script cutoff on Ruff

On the complete Ruff Git-watch rule change a8ba9e0458e60f8c406216778f0ea1cc3759c9b2, the proposed reuse of Cargo's existing worktree proof admits **zero** of the five post-script Rust processes in check, six in build or twenty in a test build. Every one of those consumers has a dependency path to Ruff's local procedural macro. Three additional rustc invocations build the three physically changed scripts themselves. The ordinary shipped Cargo also requires an imported worktree fingerprint and hashes the exact raw script stdout, which changes on this patch. There is no performance result or product change here.

For check, the untouched Linux 1.99.0-16 distribution actually ran all five consumers, three script compilers, three build scripts and three Wild links on both the edit and its restoration, and the next unchanged check reran three libraries. For build and test, the complete physical post-script rosters are from the independently published shipping-profile #233 Rust and FIFO-safe #254 Cargo study, with 8 full + 1 link-only + 7 Wild and 22 full + 1 link-only + 21 Wild respectively. This packet matches those named real commands to newly generated unit graphs for the exact -16 binary, pinned Ruff tree and corresponding command. It does not assert a fresh -16 physical build/test replay of the three-script change. The graph shows availability through dependencies and reexports. It cannot prove a particular macro ran in every compiler. All three physical roster families pass at least two inherited native search directories to each post-script command. [Full physical rosters and ordered script bytes](https://github.com/astral-sh/ohm-cargo/tree/9166ff97058eed37227dd5cc7a838e64c7577acd/benchmarks/ruff-dev-loop-20261027/build-script-targets-results). [Untouched -16 workspace check](https://github.com/astral-sh/ohm-cargo/tree/a206c6ada1df84f587618baf5b952ee3d433b40a/benchmarks/ruff-dev-loop-20261027/build-script-timestamp-current-qualification).

The shipped proof checks the complete raw stdout and parsed BuildOutput, hashes the generated tree and refuses native library paths, libraries and linker arguments emitted by that script. The consumer checks a worktree seed, no local-proc-macro marker, fresh or successfully revalidated dependencies, the old complete fingerprint, existing outputs and positive rustc dep-info files, environment and checksums. Skipping full archive reads would require complete evidence of all externally observable production inputs. A checksum of the previous source inputs only covers the file names that rustc recorded. [Exact result digest and consumer guard](https://github.com/astral-sh/ohm-cargo/blob/4c07cbf6bd91e170e3b8904eeb82436a6dbde358/src/compiler/fingerprint/worktree.rs#L93). [Creation of the local macro marker](https://github.com/astral-sh/ohm-cargo/blob/4c07cbf6bd91e170e3b8904eeb82436a6dbde358/src/compiler/build_runner/compilation_files.rs#L856).

The original seven isolated control fixtures ran all 42 before, edited, no-op, independently empty and restored commands on the unmodified -16 SDK. A watch change alone kept the result at 41. Compiler environment, generated include, outside include, a tracked local proc macro, ordered native libraries and a rewritten static archive each returned 83 on the edited side and 41 after restoration. A new six-command pkg-config fixture truly executes /usr/bin/pkg-config --static --libs. Interchanging two archives exporting the same symbol changes the ordered library directives and program from 41 to 83, with the same edited result from an empty target.

Two new cases exercise missing prerequisites even when the script announces no compiler directives, leaves OUT_DIR empty, and the old positive Rust sources retain all their bytes.

- A build script creates the previously absent competing Rust module path src/item/mod.rs alongside src/item.rs. The previous dep-info lists lib.rs and item.rs and lacks the competing path. Both check and build now fail with E0761, warm and independently empty. Restoration succeeds. This case uses no procedural macro, native library or external package.
- A fresh *different* dependency supplies a native search directory. The Rust source links a static archive through a link attribute. Its rustc command has no explicit -l and no procedural macro extern, and its pre-edit dep-info does not name the archive. The dirty package's script replaces the external native object. The library embeds that object and the real executable returns 41, 83 and 41 before, after and after restoration. An independently empty edited build also returns 83.

The absence of native archive reads from Cargo's rustc dep-info does not make those bytes unobservable. Neither a normalized watch list, an empty OUT_DIR nor excluding direct procedural macro externs allows this ordinary-worktree cutoff. A future scheme would need evidence of negative Rust module resolution and all native/archive and macro reads, or an independently proven unit scope that excludes those operations. No bound on a future tracer or a general Cargo cold build follows from these observations.

Run python3 -B verify.py and sha256sum -c SHA256SUMS from this directory. The sources of the three small adversarial runners and the unit-graph reader are included. They use a private locked offline fixture and private target/shared directories. Each runner's directory constants can be adjusted for an independent host containing the same installed SDK and Ruff checkout. The retained raw complete argv/stdout/stderr and Cargo target state remain on the collection host. The shared packet uses typed physical process records and hashes.
