# Rust archive inputs on Ruff’s private f-string edit

Stock Ohm 1.99.0-18 built the historical Ruff tree again after restoring commit 1e9287d7654f1dbe4943d67ed5ac5363c9ee2161 from its parent. An external process tracer recorded the full workforce. The 30 pure library compilers made **4,212 hard links** from their current incremental codegen work products to temporary output filenames, opened each temporary for reading and unlinked each. Each link succeeded. The Rust AST producer also removed two other objects, corresponding to the two changed codegen products seen in the source-edit oracle. The six binaries and two mixed libraries are recorded separately. The mixed compilers created 135 and 166 of these aliases. These runs were instrumented and supply no timing result.

For the parser, 78 previous object files covering 4,464,192 bytes had the same inode and payload before and after the build. Its rustc workers made exactly one successful hard link, one read-only open, and one unlink per output name. No other process issued a selected name-changing call on those 78 names. None of the parser threads called copy_file_range, sendfile, or splice. Creating these hard links transferred no payload bytes. The parser’s other 172 hard links included 171 creations in the new working incremental generation and one link from published standalone metadata to the metadata cache. The archive was published by renaming tmp.a. The parser requested dep-info, metadata and link outputs. Both before and afterward, its unit output directory contained only its .d, .rmeta and .rlib. There were zero object aliases or .rlink files under the captured unit roots after compilation.

A separate manifest-only comparison uses the original full historical edit from stock cargo build. All 31 downstream archives whose 4,306 raw input objects were byte-identical retained the exact offsets and sizes of *every* archive member. All current object offsets were therefore congruent to the old offsets modulo 4096. The object payloads total 509,086,792 bytes. Their contiguous suffixes including all native member headers total **509,345,152 identical bytes**. Every member in those suffixes has even length, so no unexamined ar padding byte intervenes. Every one of the 31 GNU symbol-index payloads matched. Every long-name table, lib.rmeta payload and lib.rmeta-link payload changed. These comparisons concern the measured original and edited files. They do not identify a trustworthy candidate reuse condition for other builds.

An ordinary compiled C caller discriminates two contents of the same file size. Replacing the source pathname atomically while restoring its old mtime leaves the existing hardlink at 17. Lazily reopening the source pathname yields 29. A descriptor acquired before replacement yields 17. In the separate cross-filesystem experiment, a real failed hardlink returned EXDEV, and the physical copy retained 17 after an in-place same-inode, same-size, backdated overwrite. An early source descriptor and the source pathname both yielded 29. Rust implements a physical copy after failed hard linking. Any proposed direct-input change must preserve the inode acquired for the successful hardlink case and retain the file-copy behavior for its failure path. The explicit filename, current metadata and symbol-index obligations are independent of these controls.
