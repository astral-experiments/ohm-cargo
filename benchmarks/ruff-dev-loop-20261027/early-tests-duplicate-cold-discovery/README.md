# Thirteen repeated compilers on the initial full Ruff test build

Two separately empty, unmodified full-workspace test builds each issued 636 ordinary full rustc commands. Grouping each successful exec by its entire executable path and argument vector yields 623 distinct values and thirteen repeated integration-test commands. Each repeated target appeared exactly once in Cargo's 619-unit JSON stream. The complete argv (including output path, both own-library externs, profile, metadata suffix, features and all compiler options) was identical within each pair. The export records the full-argv SHA-256 and both child IDs, relative source, Cargo package, target kind, profile, feature list and compiler metadata/disambiguator.

Both prior components in arm D produced 25 successful compiler exits and one exit 1 among the 26 duplicated processes. The first attempt at Ruff's `integration_test` produced no Wild invocation. Twelve native output paths received Wild twice. With both proposed observer components in C, all 26 full compiler processes exited successfully, and Wild linked all thirteen identical destination paths twice. The complete cold number of Wild invocations was respectively 200 and 201, each with 188 distinct absolute output paths. One Wild in D has no retained parent SIGCHLD status. Every observed Wild terminal signal indicated exit 0. The Cargo commands themselves both succeeded.

The parser/formatter fixtures and mdtest declare `harness = false` in Ruff, so their repeated compiler argv omit `--test` while Cargo correctly reports test targets. The 13 sources were five ruff_text_size cases, ruff_python_parser and ruff_python_formatter fixtures, ruff_cache cache_key, ruff_server document and e2e, ty_server e2e, ruff_mdtest mdtest and Ruff's integration_test. The first-party Rust target's output basename/ID is insufficient to prove a duplicate; the exporter compares complete native destination strings and complete Rust argv first. For three selected C pairs, two linkers had different temporary resolver files and rustc CGU nonce paths while linking the exact same destination. A previously collected command trace records the child executable/argv and parent SIGCHLD receipt but not all environment values or the contents of each dependency at the moment it was consumed.

These are descriptive cold observations from the previously published, unscored H5 preflight c1a13cbbc50d3729f89ac2c78441b6954ab57144. The parent Signal statuses distinguish a compiler that actually exited 0 from a successful exec system call. The compiler proof optimization under the performance study changes first-repeat `ron` work and leaves these cold duplicates present in both arms. A source-level candidate cause is Cargo's provisional early integration-test policy, which discards already-produced output when the consumed library fails its prior unused-extern test. The chosen fingerprint logging did not collect this policy's trace target, so attribution and applicability of any future optimization are unverified. No percentage reduction is measured or projected here.

Run `python3 -B verify.py` to check the typed dataset. `export.py` is the read-only census of the original full exec-only traces, using the `replay_processes.py` parser in the H5 preregistration. SHA-256 binds exported files, full argv values and raw donor process/JSON records. Complete command-line/environment dumps have not been included.
