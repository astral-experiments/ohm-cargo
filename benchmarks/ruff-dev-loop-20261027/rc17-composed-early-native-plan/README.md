# First Ruff workspace test selection with the two Cargo drafts together

The earlier test found that Cargo could compile the same `ty_server` integration test twice after its normal library had already finished. Draft #260 checked the scheduler’s completion state before choosing that speculative compile. Its published wall-time result used the 1.99.0-16 release base. Draft #261 changes the next release’s work on an unchanged graph by forcing any previous foreign-span observer to compile. This separate experiment asks whether the duplicate integration compile still occurs and whether #260 still removes it on that corrected graph. [Performance draft](https://github.com/astral-sh/ohm-cargo/pull/260) · [Correctness draft](https://github.com/astral-sh/ohm-cargo/pull/261)

Use the published 1.99.0-17 SDK, Linux x86-64, the pinned Ruff source, eight Cargo jobs, and sixteen fixed CPUs. Build the test workspace excluding `ty_server` first, validating that the normal library exists while its `e2e` executable remains unbuilt. Restore the same seed independently for both Cargo binaries. Reverse the complete historical Ruff test edit, then run the ordinary full workspace test build and a subsequent unchanged test build. Collect every compiler/linker execution and exit, the 619 reported units, 102 selected executables and all 110 ELF file digests. List the relevant test harness. There are no test-body or elapsed-time measurements in this protocol. [Original source and command](https://github.com/astral-sh/ohm-cargo/tree/1844efed56043bca3add46f9ccac806a17af829c/benchmarks/ruff-dev-loop-20261027/early-tests-completion-wall-plan-v2)

The control is the verified Cargo from #261. The treatment applies the three-file #260 patch to the same source. Verify the source, builder and treatment binary before using the treatment. The previous release’s native results and timing do not enter this comparison. `ruff_worker.py` uses the private host paths created for this experiment.
