# Two-crate reproduction of a cached procedural macro source allocation

A local derive parses the one-character string `"0"` into a TokenStream, discards it and returns no tokens. Its consumer contains a derived marker plus an unrelated function. After a genuine ordinary Cargo build, physically copy the state twice, change that function from returning 7 to 8, and empty only the consumer's Rust incremental directory in one copy. Both arms run the same `cargo +ohm build` at the same logical paths with the same already-built proc-macro image. None of the packages has registry dependencies. Both local trust overrides are unset.

In the basic case the edited consumer has two different private hashes on published Ohm 1.99.0-14, the release-matched #232 compiler, and release-matched #233. The warm value is `007277d69ab548110d50f0ac9b70d0d2` and the clean value is `fbca92294f01e51acf9d3f705bdce247`. The public hash stays the same within each build pair. Replace the discarded parse with the programmatic integer literal constructor, or disable Ohm defaults while keeping the original derive, and the histories agree.

An ordinary Rust bridge is compiled against each edited producer. Fresh ordinary callers cross both bridges with both producer images. On #233, the own-history callers print 8 and both crossed callers fail with E0460 naming the producer required by the bridge. All four work on both earlier compilers, whose ordinary bridges accept the matching public identity. This distinguishes the pre-existing private hash discrepancy from the #233 cross-image failure. This experiment did not demonstrate spontaneous reuse of an incompatible prebuilt crate by a single Cargo target.

A second specimen uses a later `include!("late.rs")`. A function-like macro formats the included token's stable Span Debug value and embeds that string in native output. Both #232 and #233 print `8:#0 bytes(373862..373872)` warm and `8:#0 bytes(373864..373874)` with the same source and an empty incremental session. Both negative controls print matching values across histories. On #232 the two crossed callers also succeed and exhibit the recipient library's own position. Omitting this synthetic file solely from the crate hash would leave the observed native results different.

The five completed variants contain all Cargo and Rust invocations, exit statuses, raw separated compiler metadata, stdout, stderr and native runtime output. Exact tools are recorded per variant. The published R14 binary, frontend and library hashes match the release installation. The #232 and #233 driver controls used the same Cargo on the same H3 host. Separate directories preserve the initial older-bridge expectation that falsely assumed old readers also pin private hashes, and a first fixture construction with a doubly qualified `proc_macro::Literal` import. Neither contributed an accepted observation.

Run `python3 -B verify.py` on a downloaded copy. The scripts under `programs/` can rerun each fixture with `--out <new-private-dir> --rustup <private-rustup-home> --sysroot <installed-sdk> --cargo <cargo-binary> --driver <driver-library> --driver-soname <SDK-library-basename>` on Linux with bubblewrap. That rustup home has `toolchains/ohm` pointing at the SDK. Use `--report-old-semantics` with v2 for earlier compilers. This package contains no timing measurements.
