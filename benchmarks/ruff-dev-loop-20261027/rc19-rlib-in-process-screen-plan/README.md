# In-process GNU archive writes on a real Ruff edit

Run the ordinary `cargo +ohm build --locked --offline -j8 -p ruff_linter` on Ruff `1e9287d7654f1dbe4943d67ed5ac5363c9ee2161`. Each pair changes or restores the complete historical commit relative to `57d800be552a88751e7ecd06fc87b44714536033`, then repeats the unchanged command immediately. The measured stock output window was 167–169 ms on the Genoa host and 463–466 ms on the Milan host. A previous loader-based trial routed existing registry crates into different directories and stopped before timing. This experiment passes the last uplifted archive to the actual compiler through Cargo. [Ordinary output windows](https://github.com/astral-sh/ohm-cargo/tree/671c8b044a7338ccbf11d2011f6dc367874aa659/benchmarks/ruff-dev-loop-20261027/rc19-rlib-ordinary-window-results) · [Loader qualification](https://github.com/astral-sh/ohm-cargo/tree/6f633f4d30e27aad6106768e1cad0dc0ffb54f07/benchmarks/ruff-dev-loop-20261027/rc19-rlib-package-hloader-native)

Both arms use the same private stage1 compiler with the checked writer and the same unmodified Wild. A uses the release-profile Cargo built from `235f9228651b74c591e6f62cae4c9b761448dd2d` and therefore writes the archive normally. B uses the same Cargo build recipe with the single change in `0299c77b2ca9707e82bc418976399fdbc75611d8`. For a selected debug rlib, B supplies the surviving top-level archive path after confirming compiler support. The experimental Rust source is `ae76b292cb224008e8188a07143797f7a4ce0ec5`, based on `5cf1bf9cd196046897a7aeeaf128833d6a464dfe`. The Rust and Cargo patch SHA-256 values are respectively `2eb0b9bc60164b4646b7c00f259dc84d787d76493f5a16e915a52c11ab1e8315` and `b413810d301ead9405dbec5b50c565184702dba0f9af3d14b33e8d347fa2c69d`.

## Admission

Verify the finished compiler images, ordinary rustup proxy and package Cargo identities on each host. Preserve the stock Wild executable. Reproduce the 15 byte, seek, descriptor and file-size-limit cases with FICLONE both succeeding and returning unsupported. Exercise an actual Rust archive over 64 KiB with a wrong, old, correct and omitted prior. Compare with an independent default write from the same compiler and run an executable that changes its answer after a real edit. Record FICLONE reaching the actual private temporary archive.

Run the Ruff package in ordinary unprivileged accounts on separate Btrfs volumes at the same canonical paths in each arm. Seed both arms from one verified original state with independent writable inodes. Isolate Cargo home, target and shared build state. Bind the different Cargo executables at one canonical path. Keep the effective environment, eight CPUs, rustc command and loader identical apart from the one experimental option for the selected linter. A separate clean build of each source state must yield the expected real SIM222 lines. Authenticate all 248 units, declared filenames, 10 dirty crate identities on the edit, zero on the repeat, the caller's actual rlib inputs, output and exit. Preserve all raw executable differences between warm and clean builds.

Before opening the screen on each machine, require the actual A/B original, edited and restored archives to match pairwise, and genuinely observe the candidate kernel clone. Require the prior source inode to preserve its original bytes when held open across publication. Trace separate qualification commands outside timing. A destination symlink or a changed prior must never substitute its bytes for the current compiled objects. Any eligibility, byte, environment, resource or native behavior mismatch stops the study with its raw evidence.

## Eight paired edits per host

Use the fixed orders printed by `python3 -IB screen.py genoa` and `python3 -IB screen.py milan`. Each host has four forward edits and four reversals. Both directions balance AB and BA. Time all 32 ordinary Cargo commands per machine with an outside monotonic clock. Observe only the selected output directory with the already published inotify observer on a spare CPU. Keep source edits, hashing, compiler traces, native callers and clean builds outside the clock. Every pair must reproduce the same exact archive in both arms and the appropriate native verdict. Never replace a measured sample.

Score the lower bracket of A's archive time minus the upper bracket of B's time for each edit, divided by A's full edit-plus-repeat time. For a release-profile trial, both machines must recover at least 1% of the loop by this conservative median, improve the archive in at least six of eight pairs, and have a median treatment/control full-loop ratio at most 1.02. Publish all qualified observations and failures. This is a stage1 feasibility screen. A product performance PR requires a separate preregistered study of matched optimized production toolchains, with a statistically significant whole-command benefit on both machines and an unaffected-filesystem control.
