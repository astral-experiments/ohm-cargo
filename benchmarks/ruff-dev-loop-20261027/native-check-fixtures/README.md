# Native-to-check metadata collision

The two fixture directories can be copied independently. Each runs with ordinary `cargo +ohm build` followed by `cargo +ohm check`. Use a fresh private `CARGO_TARGET_DIR` and separate `CARGO_BUILD_BUILD_DIR` for each independent sequence. The checked-in locks match the registry versions in the real Ruff graph.

* **Local workspace.** Leave the two Ohm trust settings unset. The default Cargo dev profile, a mixed rlib/cdylib leaf, an rlib bridge, and a binary importing both reproduce the release collision. Removing `cdylib` from the leaf gives the pure-rlib control. An independent check with both directories empty succeeds for both. The same pattern holds with Ruff's opt-level=1, line-tables-only, LTO off. Four independent native programs printed 7.
* **Registry.** One library returns `p.project?.requires_python` as a direct `pep440_rs::VersionSpecifiers` while consuming the real `pyproject-toml` metadata. The released binary and both PGO/BOLT drivers fail the warm check with `CARGO_UNSTABLE_OHM_PROC_MACRO_TRUST=all` and `CARGO_UNSTABLE_OHM_NATIVE_TOOL_TRUST=all`. Exact R14 succeeds with both removed, producing only one pep440 metadata version. The separate headers and argument-factor experiment use the real registry pep440 producer in a hybrid three-member project.
* **Root identity.** The compiler intentionally distinguishes native and check metadata despite a common stable crate ID. In the one-factor tests, changing only the extra filename changed the public hash, removing only link emission changed both hashes, and switching only embedded metadata changed the private hash. Both frozen compilers showed these signs. The matching host-only control succeeds, and exposing the same dependency in a bridge's target Rust API creates the collision.

The recorded invocations add `--offline --message-format=json -v` to retain an artifact inventory; no rustc wrapper is installed for either failing fixture. All elapsed time is excluded. References to an opaque wrapper in the comparison identify a diagnostic control which bypassed cross-mode promotion.

The fixed Cargo was also run with both supplied compilers on the registry, host-only/target and disjoint-root controls. The first fixed warm check succeeds, and each repeated registry, host and disjoint check remains fresh. Both independent empty registry checks agree and their repetitions remain fresh. The disjoint-root control preserves exactly which units stayed fresh on the unaffected native branch. The frozen Cargo hash is in fixed-cargo.json.

An intentional application error returning Option<Version> instead of Option<VersionSpecifiers> produced the identical full structured E0308 diagnostic across the warm and independently empty state on each compiler. Restoring the original return type passed again.
