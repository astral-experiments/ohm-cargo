# Registry selection and compiler-history controls for the mixed Ruff build

On pinned Ruff `93526150df07`, independently rebuilt native libraries for the same historical parser edit carried different private Rust crate hashes. An ordinary Rust bridge and a fresh executable made the difference observable. This packet contains the unscored follow-up to the original three-arm rejection and the prospectively registered registry matching experiment. The original full-workspace timing schedule remained closed. No Ruff or registry code was changed. ## Cross-compiler registry inputs

A used Cargo `0f237cc3` with compiler driver `dec72d1e` from Ohm Rust #233. B used parent Cargo `dd5cab15` with the candidate compiler `7c31057e`. C used `0f237cc3` with `7c31057e`. Each full-workspace command used the same released frontend, linker, profile, logical target and Cargo paths. The registered workload reversed the complete three-file change `3ea20f6161cb` in the bound Ruff source view.

1. Selecting `get-size-derive2@0.11.0` as a standalone root gave a different Cargo unit and different rustc arguments. A second attempt to reuse B's arm-specific registry seed on A stopped when ordinary Cargo chose its authenticated namespace for the other compiler.
2. The registered selection took 23 genuine producer compilations under A. The first 22 outputs differed from the fixed whole-plugin SHA-256 and their unscored commands were interrupted after Cargo advertised the product. Attempt 23 completed the full 501-artifact build. Six distinct, retained whole-plugin digests correspond to six distinct native `.text` digests. The winning whole plugin matched B and C exactly. All three returned the same first conflict in a real derive invocation. Every attempted producer, its rustc arguments, serial order and terminal Cargo output is present.
3. A, B and C each started another ordinary build in a physically independent workspace-cold state. The seed held 479 registry unit directories with 5,524 files from 346 verified package archives. Its manifest excluded every workspace fingerprint and artifact. Each arm reported 433 fresh registry and 68 dirty workspace artifacts. All 68 actual compiler jobs compiled workspace units. B and C used identical registry inventories.
4. Workspace-cold B and C passed the original mixed-output gates for both FFIs, raw mixed metadata, ordered native object payloads, symbol-index membership, all six ELF products and both ordinary Rust reader directions. Six unrelated workspace metadata files differed internally. Their compiler-reported identities and dependency credentials agreed. A differed from B and C in 87 raw Rust library outputs, including 43 registry outputs. Five first-diverging registry roots had equal upstream credentials but different private identities. Each has a real rustc dependency on an equal-content build-script-generated Rust input under a different authenticated output path. The Rust-driver performance contrast was ineligible.
5. With both arms using the same compiler and Cargo, B's historical warm edited state still failed the strict raw mixed-metadata gate against workspace-cold B. Of 24 bridge and caller commands across warm B, cold B and cold C, 16 succeeded and eight crossed the incompatible warm/cold histories and failed with E0460. The three-arm workspace-cold comparison also had 16 successes and eight E0460 errors. Its failures were A↔B and A↔C. The case-by-case compiler exits, actual crate names and Rust output are in `mixed/`.

## Parser incremental state

The warm and cold parser `rustc` argument lists and mounted source bytes matched exactly. Of the direct arguments to `--extern`, only the separate AST `.rmeta` bytes differed. AST's decoded public/private identities, stable crate ID and upstream credentials agreed.

Four native `cargo +ohm build --locked --offline --message-format=json` commands compelled Cargo to re-run the parser on independently cloned warm targets. The parser's canonical incremental path stayed fixed. The two factors were the presence of its previous incremental directory and the actual AST `.rmeta` chosen from the real warm or cold run. Link-time AST inputs stayed fixed. Each build advertised 501 artifacts, compiled the same parser with exactly the same rustc argument list and kept AST fresh. The workspace-only source overlay and the Git index match in all four cases.

Eight fresh callers within the same incremental-directory condition compiled and printed the real edited diagnostic, “Bytes literal cannot be mixed with non-bytes literals at byte range 0..18”. All eight crossing conditions failed with E0460 naming `ruff_python_parser`. These controls isolate the source of the identity difference to the parser's incremental state under this particular driver. They do not establish which part of the compiler generated the different hash or a failure in an ordinarily scheduled working tree.

## Files and replay

Run `python3 -B verify.py` in this directory. It recomputes the checksum manifest, registry selection, inventories, full-command counts, all 48 mixed and 20 parser external-command outcomes, and the four parser results. `seed/` holds the true Cargo JSON and declared compiler/build-script closure. `matched-plugin/` records the native input, diagnostics and compiler-generated source dependencies. `mixed/` includes full-workspace reports, exact hash-off caller arguments and compiler diagnostics. `parser/` includes original and edited file hashes, original and cold compiler arguments, raw content-addressed parser metadata and decoded headers. Use the original worker for the canonical Linux toolchain resolution and source-bound historical fixture. The repositories and release inputs require access.
