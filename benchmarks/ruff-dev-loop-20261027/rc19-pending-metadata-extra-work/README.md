## A narrower design to test

Keep B’s conservative completion and failure decisions. A possible refinement reuses the existing conditional-metadata queue edge for another narrowly defined case. A dirty check library with a previous valid local hash, an existing exclusively owned prior metadata generation and no already-established changed dependency has something to gain from waiting. When that library would otherwise start from plain early metadata of a dirty check-library producer, it can request `Artifact::ConditionalMetadata`. Cargo currently enrolls such an edge for a consumer itself eligible for dependency-only early cutoff. Intrinsically dirty producers of a generation can take the plain early-metadata edge instead. Index and literal have an initial unit-dependency configuration change. The corresponding reason for graph, ty_test and ty_project is their target configuration change. [Queue selection](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/job_queue/mod.rs#L457) · [Prior successful generation capture](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/fingerprint/mod.rs#L1157)

This uses #71's existing rule. If the previous hash equals the current one or a valid comparison is missing, the conditional notification waits for the whole worker to succeed and publish its decision. A changed hash with metadata already produced can release its consumer early only after invalidating the previous committed hash and marking the producer changed. If another ancestor still ends uncertain B continues to force rebuilding. Previous changes, real failures, malformed hashes, the separate deferred test rules and ordinary access constraints must retain their existing treatment. Restricting enrollment to a reusable, dirty, metadata-only check closure can avoid delaying freshly empty builds. It can still serialize much of a real edit with unchanged local interfaces. No execution here established its cost or that it recovers all five skips. [Existing changed-hash protocol](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/job_queue/job_state.rs#L256) · [Success release](https://github.com/astral-sh/ohm-cargo/blob/235f9228651b74c591e6f62cae4c9b761448dd2d/src/compiler/job_queue/job_state.rs#L349) · [Ohm Cargo #71](https://github.com/astral-sh/ohm-cargo/pull/71)

An additional current mtime read cannot establish what a pending producer will commit. Leaving an ordinary timestamp but immediately advertising `BuiltUnchanged` also fails to account for changed inherited trait implementations. The existing checked-in transitive fixture makes a previously valid consumer report E0034, even though the middle crate's own API is identical. Both current arms separately matched clean E0624 on the historical real AST/index private-method control. Any new scheduling experiment should also test a producer which first emits metadata then fails, subsequent revert/retry, the E0034 case, and both real manifest directions with immediate repeats.
