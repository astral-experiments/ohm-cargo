# Timing a finished-producer guard on Ruff test builds

This protocol measures two ordinary `cargo test --no-run` workflows on Ruff at `93526150df`. In the first, a developer selects the full workspace after a test-only source edit, with the normal ty_server library already built. In the second, the workspace starts with an empty target and build directory. Both use eight Cargo jobs on the same 16 pinned CPUs.

The source-matched parent and guarded Cargo use the same PGO data, packaged release-16 compiler and packaged Wild. Two independent builds of the packaged parent produced identical bytes. The treatment changes Cargo's choice to speculate when the library has already finished. [Release build and source provenance](https://github.com/astral-sh/ohm-cargo/tree/a5f4d61e00f43733b5f5f9b724fd6844ab00a0fd/benchmarks/ruff-dev-loop-20261027/early-tests-matched-release-subjects) · [Independent released-16 process census](https://github.com/astral-sh/ohm-cargo/tree/1a7be9ac0c14e576d0d72378aac3e3cde618a52f/benchmarks/ruff-dev-loop-20261027/early-tests-16-discovery-results)

The first-selection experiment has 24 adjacent pairs and the cold experiment has 12. Their order, stop conditions, correctness controls and two-sided statistics are fixed in plan.json. The build clock wraps only the ordinary Cargo invocation. Every measured workspace build is followed by an audit of 110 ELF files and final freshness. Three controls for the analyzer exercise a null effect, a slot-order effect, and a known 40% speedup.

The unscored cold parent exposed a Python reader error on the first ELF with differing raw bytes. The mmap implementation supports `find` for locating the NUL terminator in a section name. The corrected reader bounds the search by the ELF string table. It compares the same two fields as before. A mutated `.text` byte still fails. All five existing Cargo invocations and their original bytes are retained, and no timed slot started.
