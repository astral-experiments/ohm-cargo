# Conditions for a future Cargo change

A release-matched no-op needs to skip a real native job and still handle a real changed program, a changed native-library search and a failed link. These are proposed admission gates. The evaluated Cargo had no such optimization.

## Native admission

1. Use a fresh independent fixture at Ruff `93526150…`, a downloaded official -18 SDK, unchanged packaged Wild and a matched Cargo control. Bind each product’s source, release recipe, executable, compiler, linker and registry SHA-256 before any timing. Keep all source edits in disposable Ruff snapshots, leave ordinary profile/linker/trust settings untouched, and use a single canonical project/target/cache path for both arms. First demonstrate that both the unchanged scoped `cargo +ohm test -p ty_server --test e2e --no-run` and whole-workspace `cargo +ohm test --workspace --no-run` actually schedule the e2e as expected; record the scoped counts instead of inferring them from the workspace.
2. Trace separate native commands. In the unchanged full workspace require all 619 logical artifact rows, 102 executable targets, 110 complete workspace ELFs and the same test listings as the independent reference. An e2e-only patch leaves the real `ron` compiler and 49 other cached links in place, and eliminates both e2e’s cached-compiler and Wild processes. Report actual full rustc, cached rustc, gcc/collect2 and real stock Wild counts. A path that still launches stock Wild for resolution reports that process and only claims the phase it actually skips. Repeat five times to detect one-off training, stale publication and delayed invalidation. Include authenticated registry outputs. Require previous successful output and an authenticated previous recipe. First-ever links, missing evidence, interrupted publication, missing outputs, a prior error or an overwrite of the destination must force a full conventional link.
3. Reverse the genuine three-file Ruff commit `83a3afc3156d73ae4296f3fa74ede28e4c72bfcd`, restore it and repeat in each arm. The changed e2e must be newly linked and match a forced conventional link on an independent copy of the very same input state. Compare the full ELF and 200-name listing. Run the standalone `ruff_python_trivia` `.rlib` and `.rmeta` callers and check the changed RET505 auto-fix in the real Ruff binary. Also include a changed `ty_server` test body or list entry and prove its new executable reports the new test, because an unchanged listing alone misses the real dedent edit. Exercise two independent target stores and at least one second historical patch touching a different consumer. For each changed case report whether the normal rustc was full or link-only.
4. On the real e2e force earlier valid `psm/out/libgcc_s.so` to exit 83 and later an invalid replacement to produce the ordinary native diagnostic. Follow removal through exact restoration. Preserve `ron`, all cached Rust codegen inputs and all previous resolved native files throughout. Rerun these controls in the release-matched package workflow as well as direct replay. Also introduce an earlier operand through a nested relative GNU `INPUT`, a changed DSO without SONAME, a requested map/depfile/layout, an explicit wrapper/custom linker or changed native build-script arguments. Check same-length/backdated replacement of a consumed file and executable; a missing executable bit on a helper; an interrupted output write and a stale/missing/corrupt witness. Unrepresented options and failed/nonregular file access must run the normal toolchain. A new input appearing between producer observation and snapshot sealing must either be physically excluded by enforced immutable ownership or be seen by the actual normal link. Test both A→B and A→B→A with synchronization and an independent clean program. A final-path hash taken after the process is insufficient. Expose any changed filesystem/linker side effects.
5. For an early Cargo return preserve the appropriate published executable and hardlink identity. Do not modify an output or silently force a different Wild worker grant. Report any previously catalogued alternative full raw bytes with the exact source/recipe and ordinary same-input worker controls. Register any allowed finite -18-native output intervals before scoring, attribute every differing byte and require all other bytes to agree. A new unclassified output stops the cohort. The earlier -17 catalog cannot justify differences in a new -18 binary.

## Paired wall comparison

Use ordinary `cargo +ohm test --workspace --no-run --locked --offline -j8` as the single primary endpoint. The upper limit on jobs for an e2e-only patch is one cached rustc and one of the 50 actual native processes per unchanged command. This is not an elapsed-time estimate. The scoped ty_server command is a prespecified descriptive endpoint. Report its median and traced mechanism separately. If it is intended to support a distinct claim, preregister a second balanced cohort and a correction for both comparisons in advance.

* Freeze two release-profile subjects with identical compiler, SDK, Wild, directories, cache semantics and flags. If both Cargo and rustc must change, require both single-component ablations separately, then register the complete interacting design before scoring. Register absolute runner revision, exact package checksum, host, CPUs, filesystem, disk/physical-copy budget and outside load. Two official source controls must produce either the same bytes or an independently established predeclared finite raw set.
* Seed and train both arms using real Cargo. Time and report the initial acquisition/cold training separately as a cost control, also compare at least one mandatory genuine changed link. Register the measurement history as cold plus two unchanged invocations, then sample one unchanged invocation from a separate physical clone of that frozen warmed seed for every slot. Adjust the training count before registration if authentic native receipts establish a longer, stable training cycle. Never share writable state between arms. Perform independent full copies or verified private CoW copies of the same storage class, then mount at the same logical locations. Validate SIGKILL/downgrade/recovery outside the clock.
* Use 24 adjacent pairs, exactly 12 in each order, with a fixed shuffled schedule. Pin the ordinary Cargo command identically and reserve the full host for both arms with a native lock. Measure from immediately before process spawn through exit via `perf_counter_ns`. Preserve exit status and stderr for every slot; commands inside the clock have no JSON event flag, strace, validation, test bodies or wrapper. Verify all outputs and cached recipe proofs after every slot, then run a separate traced follow-up to assert its physical work and diagnostics. Capture the distinct first-training costs, warm restored workflow and a native failure outside measured commands. Stop on the first failed gate and retain its raw inputs and clocks without a partial p-value.
* Use the paired geometric mean of candidate/control wall ratios, individual command medians and 50,000 paired bootstrap draws for a two-sided 95% interval. Test with the exact 2,704,156 order assignments preserving the 12/12 balance. For one performance claim require at least 16 favorable pairs, two-sided p < 0.025, and the lower 95% improvement over 1%. For trained builds also register a loss tolerance for genuine misses and the first cold+repeat cycle before timing. A useful starting review threshold is a conservative upper one-sided 95% bound of 2% for increased geometric-mean elapsed on each nonoptimized endpoint. Freeze real costs, allowable histories, test obligations and what a release claim means before the product can be admitted. The tested exact analyzer from the previous independent -17 campaign uses this pairing model. No implementation, wall grant or timed cohort is attached to this proposal.
