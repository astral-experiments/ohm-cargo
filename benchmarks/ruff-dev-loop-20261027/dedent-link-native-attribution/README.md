# Where a real Ruff trivia change goes during linking

Reversing and restoring Ruff commit `83a3afc3156d` changes the compiled body of `ruff_python_trivia::textwrap::dedent_to`. Ordinary Linux Ohm 1.99.0-16 still launches two final native links under `cargo +ohm test --no-run -p ruff_python_parser --locked --offline -j8`. All four Cargo-edit/layout-test executable hashes match the raw discovery outputs. The first full release installation, source patch and ordinary-command baseline are in the [release discovery record](https://github.com/astral-sh/ohm-cargo/tree/565b5e80e7c4ebb1c2c7e99bc8c505353503af50/benchmarks/ruff-dev-loop-20261027/dedent-16-discovery-results).

Wild's layout sidecar identifies the chosen physical archive members. Both test executables select the same 30 out of 41 native trivia objects. The one changed object stays outside both selections. Across the edit its 17 changing ELF sections include the actual function, relocations, exception data, source locations and debug data. All 221 ordered GNU symbol-to-member associations match in all three generations, and the other 40 codegen payloads match. The 111 directly mapped fixture ranges and 108 parser ranges from trivia keep their exact output addresses. Only the ordinary external caller selects the changed object. Its actual retained function changes from 1,715 to 1,712 bytes. Its executable hash and the string it prints both change and then reproduce on reversal. The complete `.text` sections are included. Only hash and structural receipts of the full `.rlib` are included because the archives embed the build machine’s private registry path.

All four native Cargo output destinations already existed at Wild entry with mode 0775 and one hard link. A second unscored capture matched both golden outputs in the reversed direction. Restoring the source produced another parser ELF with the same `.rodata` contents but its section-header entry size changed from 8 to 0 along with the GNU build ID. This stopped the secondary capture’s raw-equality gate. The release’s own saved-input replay changes the ELF interpreter filename to an archive-relative copy of the loader. Supplying the original absolute interpreter reproduced the genuine alternate parser with one worker and the genuine original with two through eight workers, three times per width. The fixture ELF matched at all eight widths. All 48 corrected raw ELF digests and Wild phase records are included. The known behavioral caller’s third raw layout hash also differed because its fresh temporary directory contained `symbols.o`; all 45 decoded rows other than that path, the complete ELF, the retained function and its runtime output match. Both original failed assertions remain in the packet.

At four workers the medians of section resolution, layout and writing together were 36.34 ms for fixtures and 21.55 ms for the parser. An intentionally optimistic native BLAKE3 hash of the actual selected ranges plus a full old ELF, followed by copying that ELF to a visible tmpfs file, took 29.96 and 11.59 ms. At eight workers the corresponding figures were 27.03/20.53 and 16.52/9.20 ms. These are native subprocess phase and component diagnostics on one machine. The two links can overlap, and the proof benchmark receives the selected ranges for free. It omits unselected symbol influence, command and runtime context, side-effect equivalence and cache acquisition/miss costs.

Run `python3 -B verify.py` to verify all packet contents. `source/` contains the actual discovery/measurement scripts. `archive-member-receipts.json` binds the original archives, their true member intervals and payload digests. `layouts/` contains the four raw Wild layout files. If the original binaries are available, `audit.py` independently derives the symbol, object and section receipts from their bytes. All wall figures here describe diagnostic component work, never a speed gain for a shipping Cargo/toolchain command.
