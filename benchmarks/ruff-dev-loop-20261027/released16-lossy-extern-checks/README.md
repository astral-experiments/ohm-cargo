# Distinct extern paths with the same displayed filename

On released Ohm 1.99.0-16, ordinary `cargo check` returned success and marked the reader Fresh after a real external library changed. A clean check of the same source reported E0308. Both crate declaration orders reproduced this. One filesystem component contained byte FF and the other contained a genuine U+FFFD. The two independent libraries were passed to rustc via valid UTF-8 symlinks and had different contents. They produced the same path in the textual .d file. The old observer record stored that path once. For the edit, the compiler input had the same length and restored mtime. The other actual library remained unchanged. [Released toolchain receipt](https://github.com/astral-sh/ohm-cargo/tree/db71638cbb6dda4752d51ca6373e234811dff18f/benchmarks/ruff-dev-loop-20261027/shipping-16-macro-results)

The experimental Cargo encoded format 3 and compiler raw-path header 1 also accepted the stale result for one declaration order. The other order rechecked correctly. Both tools correctly detected edits when the source contained only the genuine U+FFFD path. The changed checks returned the same diagnostics as their respective independent empty checks whenever Cargo invoked the compiler.

Six direct compiler runs linked both genuine libraries and printed `17 29`. The default Cargo build in this fixture stopped before publishing its reader when serializing a non-Unicode path into its link recipe. With relink-only explicitly off, the shipped native linker rejected the raw argument. The reproduced user-facing effect is a stale successful check. An absolute byte-invalid compiler argument was rejected and a relative source compiled from a byte-invalid working directory encountered the separate existing metadata path encoder panic.

Run `python3 verify.py` to inspect the frozen records. On Linux with an installed Ohm rustup toolchain, run `python3 reproduce.py /tmp/new-ohm-unicode-check` to create the source and perform the five check phases. The recorded harness used an isolated logical rustup root and includes all successful and rejected calls. The two archives contain source, command traces, native products' hashes, compiler dep-info, Cargo proofs and diagnostics. No registry package is required.
