# Identical Rust archives can require a different native link

A Rust producer rebuilt to the same complete 6,614-byte rlib and the same separate rmeta. The terminal’s cached `.rlink`, all 22 rlibs passed to its native linker, and all 35 surviving explicit object and archive inputs stayed byte-identical. Adding a previously absent 1,374-byte `libutil.a` in a different package’s Cargo `OUT_DIR` changed the executable’s result from 41 to 83. Removing the archive restored 41. Fresh full builds using the same source and effective native inputs reproduced the warm executable SHA-256 in each case.

The rebuilding producer exports a Rust function and consumes a proc macro on a foreign token. It has no build script, native code or native linkage directives. A sibling calls the ordinary C library’s `atoi` and its build script emits one normal `rustc-link-search` for its own `OUT_DIR`. The project supplies no `-lutil`, custom link script, linker wrapper or Rust flags. GCC provides `-lutil` as part of the usual Rust link. A real stock Wild worker first received ENOENT for the exact archive path; after the file appeared a worker successfully opened it. The immutable receipts include the original syscall lines, input and output digests, actual Cargo messages, native process arguments and statuses.

Each warm reference actually ran a full producer rustc, a `-Z link-only` reader rustc, GCC's collect2 and the packaged Wild. All four processes exited successfully. One transient rustc `symbols.o` had been removed after linking, so it has no surviving byte digest. The observing producer was built without incremental codegen using an ordinary Cargo package profile, matching the actual registry RON compiler mode. With Cargo’s normal incremental codegen for a local workspace producer, the whole archives changed on repeated source-identical compiles. That earlier diagnostic run is retained separately. Its runtime results still agreed with the cold references.

## Existing compiler and Cargo contracts

Rustc’s `.rlink` serialization records the compiler/encoding versions, codegen paths, crate link metadata and outputs. Stored paths refer to the files the native linker will open later. The separate `lib.rmeta-link` describes ordered object names and bundled native library filenames. Direct non-LTO static Rust dependencies are handed to the terminal linker as complete rlibs. [Serialization](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/lib.rs#L348) · [Archive link metadata](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/back/rmeta_link.rs#L26) · [Static archive handoff](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/back/link.rs#L3728)

Cargo’s version-5 relink manifest hashes the recipe and terminal CGU files. Its retained executable record uses filename, length and nanosecond mtime. The manifest has no complete certificate for transitive native dependencies, negative lookup results, GCC driver/specs, output contents or native side outputs. An unchanged producer can still be useful for propagating a typed Rust artifact fact while the current standalone `.rmeta` remains available. Earlier actual Ruff RON compiles preserved every archive byte while producing multiple standalone metadata bit patterns. A consumer authorizing reuse of a terminal executable needs separate proof for its native environment and current output. ## Replay

Run `sha256sum -c SHA256SUMS` and `python3 -IB verify.py`. The verifier reopens the original 347 archive entries, selected raw strace lines, physical standalone rmeta/rlib/rlink, native inputs, final executable, and the two prior Ruff launch projections. Run `python3 replay.py /new/private/empty/path` to build the compact sibling-search fixture on a Linux GNU system with `cargo +ohm`, Python 3.11+, GCC, `ar` and `strace`. The path must not already exist. All inputs, targets, compiler and project states are separate. The optional `--expect-eligible-skip` additionally requires the otherwise unchanged reader to skip its native link. It still requires real native links on material edits and byte equality with a fresh full build.

The original archived worker, its input checks and private target launcher are in `original-workers/`. The portable replay adjusts only its optional candidate-mode handling of a successful zero-link repeat and enforces mandatory changed/cold ELF comparisons. The evidence provides no measured performance result or new product rule.
