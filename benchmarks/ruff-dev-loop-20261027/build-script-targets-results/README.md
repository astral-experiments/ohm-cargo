# A real Ruff build-script edit leaves three libraries out of date on every unchanged check

The registered complete reversal of Ruff a8ba9e0458e60f8c406216778f0ea1cc3759c9b2 changes the Git watch rules in the Ruff, Ty and ty_wasm build scripts. This was a linked checkout of 93526150df078af7dd8fc4226cdcc469539d2001. The native compiler was the shipping-profile #233 driver dec72d1e68fdb0f8 with the FIFO-safe #254 Cargo dd5cab154b8dcd09. Each endpoint got a private copy of its independently warmed target, registry and shared state. All rows are observations of real whole-workspace commands. None of these runs was used for wall-time inference. [Input and procedure](https://github.com/astral-sh/ohm-cargo/tree/ec22176ddf1c7e220a947dae2452420aecc53bf8/benchmarks/ruff-dev-loop-20261027/build-script-targets-plan).

| Command | Fresh before edit | Edit and restoration, each | Immediately following unchanged command, both directions |
| --- | ---: | --- | --- |
| cargo check | 520/520 | 8 full rustc, 3 build scripts and 3 Wild | 3 full rustc, 514/520 fresh |
| cargo build | 501/501 | 8 full rustc, 1 link-only, 3 build scripts and 7 Wild | 0 rustc, 0 Wild |
| cargo test --no-run | 619/619 | 22 full rustc, 1 link-only, 3 build scripts and 21 Wild | 0 rustc, 0 Wild |

The three changed build scripts ran in both directions. Their own stdout changed. Removing the Git watch directives leaves the same ordered lines and compiler inputs on both sides. The three OUT_DIR inventories are empty throughout. The Ruff and Ty version commands returned the same content and statuses. The ordinary build’s ten workspace ELF files other than build scripts are byte-identical. For the test build, 104 of 105 such ELFs match. The remaining api-af65d95beac5d41b differs from the original baseline after the edit and restoration. We assign no cause to that difference. Test builds retained the same complete diagnostic for ty’s unused set_watch method.

Cargo treats the authenticated build-script result as a dependency with its own generation. On a check returning unchanged public metadata, it restored the older metadata mtime using raw script stdout. In the edit direction, the gaps between metadata and authenticated result were 85,998,951 ns for Ruff, 73,999,097 ns for Ty and 97,998,804 ns for ty_wasm. On restoration they were 107,998,679 ns, 78,999,034 ns and 99,998,777 ns. All six ordinary repeats (three after each direction) invoked those three full compilers. On each private arm, advancing only the three verified byte-identical metadata files to the corresponding authenticated result times led to two genuinely untouched checks with all 520 units fresh and zero compilers. The timing study uses ordinary commands without this manual intervention. [Registered timing and negative holdout](https://github.com/astral-sh/ohm-cargo/tree/30c4bfb6a1989da3818a2381b6cd46cd39c0e50e/benchmarks/ruff-dev-loop-20261027/build-script-timestamp-timing-plan).

The seven standalone Cargo fixtures distinguish a changed watch list from actual external effects. Their 42 commands include true clean edited references, warm edits and restoration. A compiler environment directive, a generated include, an include outside OUT_DIR, a tracked proc macro reading an outside file, ordered native link libraries and a rewritten external archive each changed the resulting native program from 41 to 83 and back. Merely changing the watched path kept it at 41. The archive and external source controls include cases with an unchanged compiler-facing stdout and an empty OUT_DIR. A general cutoff based on only those two conditions would return stale code.

Run `sha256sum -c SHA256SUMS` and `python3 verify.py`. The verifier re-derives results.json from three compressed archives of selected native execution and filesystem witnesses. physical-workspace.tar.gz has the final release binding, ordered source and script inputs, typed native commands and output digests. causal-check.tar.gz includes the exact Cargo StaleDependency messages and nanosecond readings. native-controls.tar.gz contains the small Cargo sources, commands, actual execve and runtime results, including the independent empty references. Complete raw logs were retained on the experimental hosts. The first unedited setup probe looked for stdout in the wrong directory and stopped before applying the patch. The full registered workload used the actual run/stdout path. The raw package display field `own` incorrectly interpreted the immediate parent directory “out” as a crate name. The verifier derives package names from the full build-script executable path and asserts all three independently in both edit directions.
