# Ready test links in the released Cargo scheduler

A private instrumented build of the released Cargo source recorded every registered dependency, final dependency completion, insertion into the pending queue and dispatch with an available jobserver token. The input was pinned Ruff on x86-64 Linux and the compiler and Wild came from Ohm 1.99.0-18. Cargo ran an ordinary unchanged workspace test build. There were 689 scheduler units, including 51 build-script runs and 19 doctest preparations, and 619 reported compiler artifacts. Every run had 563 fresh artifacts.

Across three independent invocations, 46, 47 and 46 of 50 native dispatches chose a smaller executable while a larger executable was pending at the same priority. The corresponding numbers of ordered smaller-before-larger pairs were 511, 458 and 541. In the first trace, the 209,048,512-byte ty_ide harness waited while 46 smaller links began. Its scheduler-ready to token-authorized dispatch interval was 3.834 s. Its position was 48 of the 50 links. The ty_server e2e test waited through 41 smaller dispatches and its library harness through 33. These intervals describe instrumented scheduling. Product wall time and resource effects require separate uninstrumented binaries.

The first and third traces independently identify rustc, GCC, collect2 and the stock Wild by actual executable device and inode and check process completion. Each has one real full ron compilation, 50 cached compiler drivers and 50 stock linkers. The middle trace uses only in-process queue instrumentation and the names from the first verified roster. All fifty candidates are dependency-dirty test-mode units with existing regular output files. Their previous file sizes were read using symlink_metadata. Event streams retain all edge types, distinct unit IDs and pending-queue service capacity. Only operand basenames and original trace/argv hashes are exported. Positive native durations include the observing instrumentation and must stay outside product timings.

The previously built reference Cargo used the same release source and builder. Its compiler command included a different workspace artifact namespace. The diagnostic build has 22 different external file operands for the library and 45 for the driver executable, counted with multiplicity by content. Its original exact-match build rejection and subsequent diagnostic-only binding are recorded separately. The resulting executable qualifies this observation only.

Run `python3 -IB verify.py` to replay the original directed edges, priority, service capacity, terminal output lengths and kernel-observed process counts.
