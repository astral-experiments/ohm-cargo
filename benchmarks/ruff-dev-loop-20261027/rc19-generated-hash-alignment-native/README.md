# Native qualification for aligned BLAKE3 reads

Both optimized Cargo builds use the qualified 1.99.0-19 Cargo source, published 1.99.0-18 Linux compiler, the same PGO profile, native toolchain, literal Rust arguments, external artifacts and display stamp. The candidate changes the first read after a partial 16 KiB BLAKE3 subtree. The first and second independent file observations both run through EOF. The complete release source, workload, numerical thresholds and schedules were registered before qualification in Git commit `2d40c0ba8f68ba2bfadc489db876b49f5c442de4`.

The two Linux hosts independently cold-built and warmed their own targets, registries, SDK and shared build directories at identical logical source, registry and output paths. For each image, 182/182 units were fresh. The actual Cargo process had uid/gid 1000 in the login mount namespace. All ancestry, both executable identities, eight permitted CPUs, 118 actual cached registry manifests, one cached Git index and the remaining registry prerequisites are recorded. Each host independently traced two rounds of 7,918,933 generated bytes. An ordinary Rust caller consumed the expected pydantic stub through the compiled public library. Four binary-by-state combinations on each host left the complete library and metadata bytes, checksums, saved build-script generations and caller output unchanged. All 330 declared file paths and raw digests are bound per independent arm before scoring. The registered wall command checks the full map again after all 384 commands per host.

The first unscored raw cross-cold equality check failed on both hosts. All three ordered object bodies and the entire ar symbol index were identical. The ar string table and rmeta-link object differ only by the three actual compiler-session object names. The original secondary metadata matched byte for byte. For the original primary and both final cohorts, the metadata differences are fully accounted for by twelve serialized dependency hashes, both crate hashes, local reachability-table fingerprints at DefIndex 0 and 7, and the graph-independent public fingerprint. The exact compiler decoder and the sparse table layout were checked. Two independently cold-built baseline-only states on the primary reproduced changes to the same fields. The second stock control produced the identical complete metadata file as the candidate. The archive metadata ELF wraps the exact standalone metadata bytes. All six possible primary comparisons and the independent host's A/B result are retained, with the full independent stock control and candidate SHA-256 values. Pre- and post-timing checks require the exact prequalified raw files for each arm.

The adversary atomically publishes an equal-length, backdated but byte-different ZIP immediately before Cargo's second successful open. The native tracer matches the actual Cargo ELF device and inode and observes syscall entry without setting a loader environment variable. Only `ty_vendored` rebuilds in either mutation direction. Its library embeds two copies of the expected full ZIP and its standalone metadata embeds one. An independent Rust caller reads the original expected source payload on every phase. File-mode-only changes also invalidate, converge, and restore identically. The study retains both the intervening reverse edit, where the source returned to the original bytes, and the following ordinary command. The host release probes exercised 135 file size and prefix combinations, 20 changed, shortened, interrupted, erroring and short-read cases, EISDIR and ENOENT on both source functions against the locked BLAKE3 crate.

Several initial qualification attempts stopped before timing. An extra hard-linked SDK copy changed the compiler inode's ctime and correctly selected another Cargo namespace. A recreated group-writable Cargo home disabled trusted registry caches. Both errors are caught by the final worker. One early instrumentation attempt added LD_PRELOAD on the mutation command, which changed registry eligibility and rebuilt 177 units, including the ZIP producer. Those attempts were kept separately. The successful native file probes use an external tracing parent, and the actual wall protocol has no tracing, wrappers, hooks or Cargo JSON flag. The independent host archived only the study's own discontinued states; every restored archive was compared against its original files before the space was reclaimed.
