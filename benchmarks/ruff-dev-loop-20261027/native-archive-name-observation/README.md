# Archive member names affect real Cargo relinks

An unchanged Linux GNU linker script selected a 42-byte input section by its original Rust archive member name. On the corrected #233 compiler, a same-width private leaf documentation edit preserved the producer’s Rust public hash, every native object byte and the complete ordered GNU symbol-to-member ordinal mapping. Rustc emitted a fresh member name. The initial program exited 83. The ordinary Cargo edit ran one full producer and one cached terminal linker compilation through GCC, collect2 and packaged Wild. Its executable and a fresh build exited 41. The script, downstream Rust, build script and flags were identical throughout. The two linker-defined addresses moved from 42 bytes apart to equal. Both unchanged-source repeats were fully fresh. The exact three small producer archives, source files, script, toolchain and execution digest receipts are included.

An explicit --write-layout argument separately produced the same executable and a different Wild layout file after the same private comment edit. That auxiliary output contained the original then the new member name and stopped containing the old name. The exact same observation was reproduced with WILD_WRITE_LAYOUT=1 and no build script, rustflags or linker arguments emitted by the project. The plain positive control produced an identical ELF, returned 41 and issued one real link-only compile on the private documentation edit. A private body change in the same fixture kept the public hash but changed a codegen object, the ELF and its return value to 42. The edited cold reference matched.

Two earlier matched Ruff producer pairs captured the actual 36029f1c9a48 documentation edit under #232 and the then-current #233 driver 3e4b1689. In both, all 256 codegen object bodies and positions agreed and all 26,199 ordered symbol-to-member ordinals stayed equal. Exactly zero of the 256 full member names matched. The ordered .rmeta-link names followed the new archive members, the metadata wrapper changed and the raw archive shrank by 1,760 bytes. The final dec72d1e experiment retained complete workspace ELF and process records. Neither full producer archive pair nor per-object filename traces survive for that exact run. It was not rebuilt for this report. [Final matched ELF and process results](https://github.com/astral-sh/ohm-cargo/tree/483aa0b9ba35602043c2d748a3a594801b739107/benchmarks/ruff-dev-loop-20261027/parser-doc-link-products)

Rustc can emit a native artifact digest after writing a completed archive. The existing mixed-library native_rlib_hash is emitted earlier with metadata and describes retained linked static symbols. It does not hash codegen object contents. An exact archive identity can bind all ordered names, object bytes, symbol providers, bundling, metadata and toolchain, but it rejects these two historical Ruff edits. A native generation that ignores names or embedded metadata can be used only when the consuming linker and its complete effective inputs cannot observe the ignored fields. The normal raw .rlib and .rmeta must both remain current for downstream Rust.

The proposed Cargo-level whole-link cutoff lacks these observations on default GCC/Wild. Besides the captured name selectors and auxiliary outputs, a previously nonexistent higher-priority library, a modified GCC specs file and a native input changed through an already-dirty mapping can all change a link. The consumer would need an authenticated previous success for the exact output, target flags, codegen and transitive native inputs, current linker/tool and native namespace, ordered successes and failed path lookups, and an output contract permitting a skipped invocation. Unsupported scripts, flags, plugins, observable side outputs, custom wrappers and uncertain file identities must fall back. These measurements reject an unconditional producer-only cutoff.
