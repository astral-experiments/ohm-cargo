# Verifying the current bytes when writing Ruff rlibs

A real Ruff f-string edit changed the metadata and GNU archive member names of dependent libraries. All 4,306 native object members in 31 downstream libraries stayed byte-identical at their previous offsets. A Linux prototype used `FICLONE` on a prior complete archive, collected the current GNU writer's stream in 64 KiB chunks, compared every byte against its private clone and wrote the chunks that differed. It truncated to the exact current length before the ordinary atomic rename. The original public inode stayed accessible through a held descriptor. [Ruff edit and byte layout](https://github.com/astral-sh/ohm-cargo/tree/c90d9eb1ef91fda63e3f7195c80827db8050a352/benchmarks/ruff-dev-loop-20261027/rc18-parser-cgu-alias-operations)

Both implementations used the release's actual `ar_archive_writer` 0.5.2 GNU writer and the `LLVMRustGetSymbols` function from the officially distributed Ohm 1.99.0-18 x86-64 Linux compiler. The release driver SHA-256 is `a7648053cbad025c1bb0bebb7009ce9e1515bdb02e8c30bef29b52a881e5b8de`. Each constructor received the two newly generated ELF metadata members, the current member names, and the previous native object payloads. The complete expected archive files were hidden from the writer in the test mount namespace. Every product matched the independently captured complete current archive SHA-256. [Released writer](https://github.com/astral-sh/ohm-rust/blob/a4fa11bcd38280639cb94daacc125472657db6c3/compiler/rustc_codegen_ssa/src/back/archive.rs) · [Stock callback qualification](https://github.com/astral-sh/ohm-cargo/tree/2c69db443e1e2167cd3cc17de8d2f77d0b430529/benchmarks/ruff-dev-loop-20261027/rc19-rlib-llvm-context-attribution)

The byte oracle was the actual released compiler's warm edited archive for each library. All three empty-build archives have different SHA-256 values even for stock rustc, as recorded in `clean-comparison.json`. The ordinary historical warm and empty builds produced the same four native caller results and Ruff diagnostics. The writer component did not run a separate Ruff command or produce a clean-build match for these raw rlibs.

This is a single-host native component experiment on an AMD EPYC-Milan with Linux 7.0.0-38-generic and btrfs-progs 6.6.3. The command clock included process launch, member mapping, LLVM scanning, serialization, buffering, and rename. Each new output was hashed and synced outside the clock. A physical FIEMAP comparison outside timing identified extents shared with the old inode at the same offset. Each arm ran six times first and six times second per library. The complete 36-pair schedule was frozen with SHA-256 `cede7a4cb6a08977274c1ad97651eea6e54620a5ac16730c6690c659c6b3262c` before measuring. The formatter difference was inconclusive. The three four-pair blocks allow only 27 bootstrap resamples by enumeration. The package contains all raw samples to let readers examine variability.

The ordinary writer and prototype also rebuilt every library on ext4, where cloning fell back to ordinary writes. Separate parser controls covered a corrupted same-size input with restored mtime, longer, shorter, empty and read-only old files, an absent output, a symlink to a sentinel, FIFO and socket outputs, a held old inode, an injected failure before rename, and an actual file-size-limited write. Both failures preserved the entire prior archive. All correctness cases used an ordinary user with no capabilities. The performance series ran only on the Btrfs mount.

Cargo removed the previous per-unit rlib before spawning the actual compiler in each of the 31 downstream jobs. A separate top-level archive survived for each unit in this whole-workspace command. A package-only build had just one top-level archive for 148 rlibs. The component gives the writer an explicit prior inode. An ordinary Cargo build needs a way to supply an eligible origin and an end-to-end timing comparison before these measurements can support a product change. [Native incumbent lifetimes](https://github.com/astral-sh/ohm-cargo/tree/ef15880a76db776ecd61f82eae43d2c8ec60156b/benchmarks/ruff-dev-loop-20261027/rc18-rlib-incumbent-availability)

Run `python3 -IB score.py` and `sha256sum --quiet -c SHA256SUMS` to verify the committed data. `python3 -IB reproduce/portable-rerun.py --help` describes the native rerun with the six content-addressed archive bodies. Their digests, full member inventories and raw terminal results are committed here. The original archives are retained with the benchmark and are required for an exact byte-for-byte rerun. A fresh Ruff build at a different absolute location can produce different archive bodies. The earlier historical acquisition explains how to produce equivalent inputs. The private Btrfs reproduction uses Linux loop mounts and sudo for the mount namespace.
