# Cargo instruction counts after changing Ruff’s Salsa requirement

Ruff commit c890b04e575809cbff9b43975175b43dd82c3a1a raised the Salsa dependency requirement from 0.28.2 to 0.28.5. This study reverses and restores its root manifest hunk at Ruff 93526150df078af7dd8fc4226cdcc469539d2001. The checked-in 553-package lockfile keeps Salsa at 0.28.5 in both directions. All samples used the ordinary `cargo +ohm build -p ruff_text_size --locked --offline` invocation. [Upstream change](https://github.com/astral-sh/ruff/commit/c890b04e575809cbff9b43975175b43dd82c3a1a)

Each measured process was the genuine Rustup-selected Cargo on H8, with cores 0–3 and a private write layer over the original verified common one-unit target. Each scored build used the fully fresh rlib and rmeta and produced their original complete bytes. Uninstrumented pre/post controls reported one `ruff_text_size` library with no features, compiled a caller against that library and required the same ELF and exact stdout `17 29 12`. After the series, both arms were independently reopened through read-only mounts. The retained caller executable from each also ran successfully.

Hardware userspace instruction access was denied by the kernel, syscall 298 with errno 13. The accepted counts are dynamic x86 application instructions across all threads of the parent Cargo process, including linked libraries. They exclude kernel, profiler, Rustup and child execution. The kernel tracer saw no underlying compiler, build script or linker and confirmed four same-PID process images in each measured invocation. Thread starts and finishes matched exactly. The measurements give no wall-time estimate and apply to this selected build and host.

The two native clients counted 4,000,060 and 4,000,105 additional application instructions for the secondary pthread’s 2,000,000-iteration two-instruction loop. Moving that work to one fork/exec child changed parent counts by -28 and -73 and exercising eight children changed them by +117 and +94. Observed application-thread counts per measured Cargo were 3. The earlier version probe showed that the instrumentation is unsafe for forked discovery helpers with unpaired thread-end callbacks. Admission here used the short version command and required zero child processes and paired thread starts/ends on every measured Cargo.
