# A jobserver-dependent native test ELF cannot be reused freely

The rejected Cargo source was f17865112618fdbe0b78c96549f22248cda56d87. It ran with the release-profile #233 compiler and the shipped Wild 0.11.0. Ruff was pinned to 93526150df078af7dd8fc4226cdcc469539d2001. The historical standard-library edit reversed 523d83c941cbae9b7c8a10739c839a8eeda3245d. Both native WebAssembly API integration tests contain a crate-level wasm32 condition. They list zero tests on x86-64 Linux.

On the 374-unit two-package command, the ordinary edit used 14 Rust invocations and four native links. The prototype used 12 and two. One of the two retained executables differed from the ordinary full build. A repeated comparison from the same read-only candidate state, withholding only the two cached eligibility manifests, gave this Ruff API executable two distinct hashes in three forced full builds. Two independently restored shipping-control builds gave the same other hash. Each variant built 14 Rust jobs and four native links, then ran an immediate fully fresh Cargo invocation. A storage-guard interruption and a preflight with a different shell PATH contributed no measurements. The raw native binaries and inputs stayed in the private reference fixtures.

For each recorded GCC-to-Wild command, a direct replay used the same Rust CGU and SDK bytes and the captured temporary symbols object. One worker produced one ELF hash twice. Two and four workers produced a different hash, also repeatable. This happened for both actual Ruff API products. For the previously observed differing ruff_wasm output, all CGU payloads matched. The two changed fields were the GNU build ID and the section-header entry size for .rodata. The .rodata bytes themselves matched.

A native tool eligibility proof also missed three external behaviors. A direct RUSTC executable that conditionally added a cfg yielded a real active test in stock and zero tests in the candidate. A dynamic-loader diagnostic request produced separate Rust and Wild diagnostic files only for the stock API job. Removing executable permission from a byte-identical collect2 or bundled ld.bfd in a private mount caused the stock compile to use a different linker and produce a different ELF. The candidate incorrectly retained its previous ELF in both cases.

The JSON contains selected fixture names, per-process roles, output hashes, saved native-input filenames and digests, and the observed outcome of each control. The file manifest uses SHA-256. The included verifier runs offline with Python 3. These are unscored correctness results.
