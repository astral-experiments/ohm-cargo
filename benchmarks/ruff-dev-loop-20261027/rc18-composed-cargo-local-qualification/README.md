## Native cases

- The six observer configurations cover `include_bytes!`, `include_str!`, and `proc_macro::tracked::path` with a real same-length input replacement at current or preserved mtime. All six original releases executed their stale binary at 17, reported all targets fresh and launched zero compilers. The first fixed build, the second fixed build and a separate empty fixed target returned 29 in all six. The first fixed build retired the prior complete OBS1. The second recompiled only `hold_direct` and the Make depfile retained its missing sentinel in warm and empty targets. This records the intentional cost for readers that still lack a sound complete proof. Both profiles use different physically writable states copied from the same individually authenticated legacy targets. The raw exec traces are included. The offline verifier reassembles interrupted exec lines and reports compiler counts from them. The older `row.json` collector itself only counted complete lines.
- A genuine Cargo-managed build script compiled C into a registry proc-macro library. Its .text bytes changed while compiler metadata and dynamic symbols stayed equal. In a new target each candidate ran a marker-free seed at 17/0, followed by a true source edit whose derive and observing join both returned 29. Retained -17 and earlier #261 each returned the stale derive 17 alongside the correct join 29. Switching only the Cargo executable gave 29/29 immediately, through the repeat, and on an independent empty target. Each migration also tested a subsequent downgrade and upgrade. The captured actual proc-macro calls and native program values are in the per-command rows.
- During a real compiler execution a standalone metadata input was replaced after the old token was observed. Old and new external metadata files have identical internal public hash, private hash, and StableCrateId. For both timestamp forms, the initial check exited zero and the next two checks plus a separate clean check exited 101 with the same E0308. The participating external metadata products in this test differ in size. The separate six-case tests above exercised same-length replacements.
- The checked-in #260 scheduler tests passed for both Cargo images with 14 and 41 physical Cargo commands. The built-library and unused cases compiled the integration executable once, and the used case twice. Missing, malformed, and conflicting proofs each triggered two real compilers. All 17 warm-case process histories are also retained, including the setup, intermediate check when present, and final test. The checked-unused case ran two native test compiles and one metadata-only check over those three distinct commands. The test harness separately asserted the final command's retry policy.
- The checked-in exported-depfile and native-derive tests passed on both Cargo images. Against a macro-freshness-only Cargo control at the same source and output paths per profile, the final Cargo produced the same Make depfile with an escaped space, a repeated build-script input, and the lexical `src/../asset` operand. After deleting only the public depfile, regenerating it launched zero rustc or linker processes, returned all three artifacts fresh, and retained the native executable bytes. A subsequent unchanged build did the same. Paths intentionally differ between the development and PGO studies, so raw depfile equality is asserted within each study. All nine checked-in encoded-depinfo unit tests passed on the exact source.
- For tracker #202 an interposer forked a child immediately after a real exclusive ThinLTO prune lock was acquired. The test observed explicit LOCK_UN on its original parent descriptor while the child retained the inherited file description, followed by a new successful acquisition. The relevant lock implementation is unchanged relative to released -17. For #228 both published -17 and the composed development Cargo passed the actual checked-in, untraced PTY cancellation/terminal-restoration test, validating both expected shell statuses. The production paired gate was about the default macro, scheduler and exported-depfile changes.

Two attempts to use older physical target snapshots selected different release workspace namespaces and therefore rebuilt the initial historical control. Those attempts stopped before the candidate ran. The current-epoch fixtures regenerated all six false-fresh states, verified their executable and active record hashes, and reproduced stale 17 with the actual -17 Cargo before admitting each copy for upgrade. The first standalone Make observer stopped on the control because it expected an unescaped filename. The raw control showed Make escaping and a lexical relative operand, both independently confirmed with the corrected observer against the two Cargo arms. The initial unit filter matched zero tests. The corrected filter ran nine. A first attempt to trace the PTY test exited in the test harness waiting for a stopped child before delivering the tested Ctrl-C. Both actual untraced invocations passed. The displaced receipts remain in the development archive.

## Offline verification

`python3 -IB verify.py` rechecks the manifest, Cargo JSON, executable outputs, active observer trailers, exact file bytes, checked diagnostics, and process records. It prints both profiles’ individual physical compiler histories. With access to the Cargo checkout at the exact commit, add `--cargo-git /absolute/path/to/checkout` to regenerate the nine-file source projection independently. The shipped-toolchain historical issue inventory is in the separate component `shipped17-cargo-tracker-audit`.

The gzip tar files contain the original JSON and text outputs, selected trace lines and original per-process trace digests for the registry-derive and scheduler runs, full supervisor traces for the migration/Make runs, and the typed external-metadata products. The native cases concern the default feature configuration. Explicitly forcing the experimental persistent procedural-macro cache is outside the automatic-default repair. This study used unscored functional runs only.
