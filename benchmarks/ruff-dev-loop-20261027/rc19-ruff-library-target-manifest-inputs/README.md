# Stock Cargo target flags and compiler-visible inputs

This packet records how the released Linux x86-64 Ohm 1.99.0-18 behaves when removing one line, `test = false`, from a library manifest. The default value is true. Every actual command here selects the ordinary library. No command asks rustc to compile a test harness. Fresh targets and shared build directories were independently allocated per fixture, command mode and clean history. The selected compiler, Cargo, and Wild SHA-256s appear in `evidence.json.gz`. The work did not collect clocks.

| Fixture | What the ordinary compiler or tool observes | Released result |
| --- | --- | --- |
| Reexported proc macro | An ordinary dependency reexports a proc macro. The macro reads its consumer’s Cargo.toml with std::fs::read and returns a literal. Only the facade appears in the consumer’s direct --extern list. | Original 17, edited and clean 29, restored 17. The Rust dep-info omits Cargo.toml. The external metadata reader rejects 29 with E0308. |
| include_str! | Rust reads the library manifest as an included file. | Same program and type outcomes. Rust dep-info names Cargo.toml. |
| Compiler wrapper | RUSTC_WRAPPER reads the manifest and appends a real --cfg observed_test_off/on to the library compiler. | Same program and type outcomes. Rust dep-info omits Cargo.toml. |
| Module path | The code has mod selected and initially only src/selected.rs. The study adds src/selected/mod.rs before it changes the manifest. | Adding the alternative alone left Cargo fresh. With both files present the manifest edit led the compiler to report E0761, including in the independent clean target. Restoring the original source succeeded. Rust dep-info omitted the competing path. |
| Native assembly | A pure Rust library passes its actual Cargo.toml to the integrated assembler via .incbin. Each usable rlib contains exactly one object with .rodata.manifest_fixture. | Compare all four configurations and the physical section in the ledger. Both unchanged external executables and each independently linked reader used the actual retained rlib. |

The two missing-module paths are an intentional two-file example. The positive `include_str!` control exercises ordinary tracked-byte invalidation. Successful compilation alone would not characterize either the macro or native examples. Every successful build has an original program output, a second program linked against the retained library, and a digest of that exact library and the independent executable. For each assembly row the packet includes the bytes physically extracted from the archive's named object and ELF section. The four-way series explicitly separates Cargo's Ohm defaults from the effective rustc incremental setting. Defaults disabled still uses the pinned Ohm compiler.

The original build harness tried both Cargo-reported outputs in succession. Its standalone .rmeta lacks linkable code, so the last trial could fail and overwrite its per-trial status. The initial successful .rlib program output, untouched error from the additional attempt and both emitted files were retained. The supplemental reader always uses the single saved .rlib, writes to a new path and compares its stdout byte-for-byte with the initial program. The metadata-only check tests use a separate rustc invocation and retain its actual diagnostic.

`fixture/` contains the actual synthetic sources and locked manifests in their restored original state. The first generated program prints `manifest_case::answer()`; the check consumer asserts its length is 17 in a constant expression. `evidence.json.gz` contains all 77 Cargo endpoints, each external result, original integrity commitments, sanitized native argv and Rust dep-info bodies. Raw trace-file digests commit to every original trace. Names rooted in the task-private host are mapped to portable role names in projected argv, diagnostics and file opens. Hashes of original raw bytes are separately retained. These are controlled correctness tests on one released Linux toolchain.

Run `python3 -IB verify.py --mutations` from this directory. The verifier validates all 77 commands, 49 ordinary executable readers and 28 metadata/error paths, plus the full portable manifest and four deliberate corruptions.
