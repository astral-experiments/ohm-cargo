# Ruff procedural-macro edits

Build `ruff_index` and its library test executable separately with the published Ohm 1.99.0-17 Linux package. `ruff_index` re-exports `ruff_macros::newtype_index` and invokes it in its own tests. The first edit reverses the complete `rule_namespace.rs` portion of a historical Ruff formatting change. The other two edits change the diagnostic of that distinct procedural macro and the maximum value emitted by `newtype_index`, respectively. The latter two are designed controls. [Historical Ruff commit](https://github.com/astral-sh/ruff/commit/c0824de94a1c9bf7c0042625c8a46ed5eafe9794)

Start each arm from empty private state. Capture each full or link-only compiler process, Wild process, Cargo unit and reported workspace artifact. Check the generated bound with a direct macro consumer and, in the library build, through Ruff’s public re-export. Compile an invalid `RuleNamespace` use to check its actual diagnostic. List test names without executing them. Twelve commands per arm cover priming, the forward and reverse edits and unchanged commands. `plan.json` fixes the order, inputs and tool identities. This experiment measures work counts without timing or a candidate implementation.

Use `python3 -B reproduce.py --mode build --sdk SDK --ruff RUFF --cargo-cache STORED_CARGO_HOME --scratch NEW_DIRECTORY --lock LOCKFILE` on Linux x86-64. Use `--mode test` and a different unused scratch directory for the second arm. The runner mounts temporary source views and keeps the original checkout read-only.

The original registration stopped in setup before invoking Cargo. Its private `/dev` hid the SDK under `/dev/shm`. Replaying the namespace check returned 1 before binding the pinned SDK at its original location and 0 afterwards. The historical edit, controls and outcomes are unchanged.
