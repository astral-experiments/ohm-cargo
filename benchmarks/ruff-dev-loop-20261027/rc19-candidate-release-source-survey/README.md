# Existing Ohm releases and the two Ruff performance candidates

The Ohm project had 55 published releases on October 28, 2026. Every published tag mapped to one release manifest on project `main` at `885faf0af725074adc31080a1c732c60965d8bbe`, and every manifest mapped to a published tag. These manifests selected 44 unique Cargo revisions. Twenty-eight revisions were absent from the union of live Cargo branches and all open, closed and merged PR heads. [Ohm release history](https://github.com/astral-sh/ohm/releases) · [Pinned manifest tree](https://github.com/astral-sh/ohm/tree/885faf0af725074adc31080a1c732c60965d8bbe/toolchains)

At every released revision, Cargo's job queue enqueued a fixed cost of 100. The eight distinct released scheduler source files contained the same cost expression. Four released dependency-queue definitions had no historical-duration lookup or filesystem size query. The actual previous-executable size tie-breaker being tested in the private prototype is absent. The earlier current-branch and all-state-PR survey independently covered 274 product tips. [Source survey and physical queue observations](https://github.com/astral-sh/ohm-cargo/tree/7810ad4fb670d0c5278b2dcbcb1d6f56bbd4206d/benchmarks/ruff-dev-loop-20261027/rc18-ruff-native-queue-opportunity)

Twenty-nine published manifests included the generated-file hashing implementation. Three distinct released `fingerprint/worktree.rs` files contained a byte-identical `hash_file` function that did not align reads to the current BLAKE3 stream position. The other 26 published releases predate that source file. The two prospective changes are being tested on the qualified `-19` Cargo parent `235f9228651b74c591e6f62cae4c9b761448dd2d`. These source checks establish what already shipped. They do not measure the performance of either proposal. [Pinned Cargo revision](https://github.com/astral-sh/ohm-cargo/commit/235f9228651b74c591e6f62cae4c9b761448dd2d)

`ohm-release-tag-coverage.json` records release links and publication times. `ohm-release-source-coverage.json` maps each manifest to its commit, relevant paths and verified Git blob IDs, including the two historical repository layouts. Run `python3 -IB verify.py` and `sha256sum -c SHA256SUMS` in this directory. Source search and native checks are repeated before a performance PR is opened.
