# Cost of temporary Rust object filenames

A one-CPU engineering comparison used the exact 4,212 reused native ELF payloads and their temporary filenames from 30 pure library compilations in the Ruff f-string restoration. A private physical copy of each payload protected all compiler and Cargo outputs. The control created the hard links for one library, opened and checked each linked object, then unlinked them. The second arm opened the original objects up front, retained the descriptors until the corresponding simulated archive-read phase, then performed the same inode, device, length and ELF header check. Both methods examined the same source inodes in the same per-library groups. All 28 invocations, including four excluded warmups, returned the same data commitment.

The median control time was 254.909 ms and the median early-descriptor time was 87.192 ms. The paired median difference was **169.149 ms**, favorable in all 12 balanced pairs. All original clocks are in terminal.json. Each clock covered one serial pass over all 4,212 inputs, after verifying that all source files existed and that every temporary path was absent. The timer excluded process startup, preparation, directory creation and physical copying. The comparison ran on an AMD EPYC Genoa core in the native loader namespace. Compiler workers actually process libraries concurrently. The experiment omits analysis, code generation, reading complete native payloads and writing ELF or rlib outputs. It measures the cost of constructing temporary directory entries under those conditions; a whole-build effect requires separate measurements.

The direct-descriptor form only models the successful same-filesystem hardlink case. The companion six-consumer custody controls cover atomic replacement and the consequential difference on actual cross-device fallback. Other output modes or failures would need separate treatment before any compiler change.

Run `python3 -IB verify.py` and `sha256sum --quiet -c SHA256SUMS`. On the host retaining the source study, put all three files from reproduce/ and a copy of registration.json named alias-cost-registration.json under the f-string study root. Run alias_cost_prep.py followed by alias_cost_plan.py in a fresh alias-cost-v1 namespace. The preparation script creates the directory and validates all rows before running any clock. The previous complete archive trace and its full package must be present. The numerical engineering registration was communicated before these runs. This study produced no compiler change.
