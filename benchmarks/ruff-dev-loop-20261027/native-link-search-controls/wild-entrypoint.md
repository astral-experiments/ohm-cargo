The complete Ruff reversal `36029f1c9a48` at `93526150df` ran 19 native test-build links on the corrected compiler. Four Ruff CLI integration executables omit `ruff_linter` in the actual GCC-expanded GNU Wild arguments. The two historical edited phases contain 24 verified argument vectors, covering the real GCC, collect2 and packaged Wild for all four outputs. Every Wild line matched its previously published physical trace digest. The raw private argument vectors are retained separately. `selected.json` includes the program names, digests, argument classes, and ELF checks.

All non-transient ordered Wild arguments match between the two exact candidate edit traces. Three items vary in every call: GCC’s `-fresolution` file, rustc’s `raw-dylibs` search directory, and rustc’s `symbols.o`. Each actual link has 14 ordered search directories, seven named libraries and a GNU build ID. There is no response file. All four full candidate ELFs match their before, two edited and restored states. The parent’s `config` changed in `.rodata` and its GNU build ID in the final edited sample. Wild uses an actual jobserver worker count when laying out output. Input-byte hashes were not captured for every native path during those historical four test links. The separate complete captures of this historical edit's three native *build* links used a Clang wrapper. All three received a different `ruff_linter` archive across states and cannot pass a full raw-archive key.

The cost columns are the medians of three private two-CPU, warm-file replays on the same local host, after a separate instrumented stock run. The input data are genuine retained Ruff integration `.rlink` plans and codegen objects in a separate release-14 target. A mount namespace made all shared inputs read-only and supplied private output directories. The matching physical compiler reconstructed `symbols.o` for each invocation. Real GCC and collect2 expanded the invocation, and the original packaged Wild linked it. The instrumentation prefix introduces a private GCC search prefix and the test does not reproduce the historical benchmark source state. Each pass verified 80–98 million bytes, including the existing ELF, selected archives and objects, dynamic runtime files observed in the process, and the stock linker executable. Parallel BLAKE3 digest equality and all 130 prior absent input/loader lookups stayed stable in each replay. Single-worker hash medians were 75, 73, 80 and 90 ms for config, direxist_guard, resolve_files and analyze_graph. The negative-path set alone took 0.7–2.5 ms. These descriptive measurements omit cache authentication, lock management, worker-count selection, handling output side effects and some ambient inputs. The overlap among the four links also prevents summing these timings into a Cargo command saving.

`entry-negatives.json` records three falsifiers on the packaged release-14 Wild. Adding an earlier native archive changed 41 to 83 under the same normalized real GCC-expanded arguments. Adding GCC's prefix `specs` changed the real Wild search arguments and the program to 83. Removing it returned to 41. Mutating a selected archive through an already dirty shared mapping changed 41 to 83 while device, inode, mode, hardlink count, size, nanosecond mtime and nanosecond ctime all stayed equal. A modified output with its original length and restored mtime also failed the content check. `special-inputs.json` shows a real GCC LTO link opening `liblto_plugin.so` and using the `-fresolution` temporary that the four frozen ordinary links never opened. The two-byte GNU linker-script assignment changed the native program from 41 to 83 in a separate case.

A literal complete-argument key misses all four real reruns. Supporting just the three moving locations would require a prior authenticated success with inactive LTO, complete positive input bytes, complete ordered negative searches in the *current* raw-dylibs directory, and content identity of the *current* symbols.o. Path-dependent formats and outputs, unsupported scripts, unresolved dynamic-loader configuration, symlink ambiguity, inaccessible lookups, auxiliary outputs, and foreign plugins all require fallback. These proposals do not prove a shape-based rename harmless for other link invocations. A prior successful name alone cannot establish whether a newly created higher-priority provider is available. File checks must preserve kernel path semantics through symlinks and `..`.

Even when the ELF is byte-identical, an output-free hit cannot preserve stock Wild’s write behavior. Existing regular output is opened `O_RDWR|O_CREAT|O_CLOEXEC` in the retained real config replay. The earlier independent output fixture records changes to inotify events and capability bits relative to a shortcut. Returning before the real writer cannot provide those effects. A cached full-image replay could instead use the stock output creation/finish path and write the cached bytes with incumbent hardlink/open-reader behavior, but it would still need full input/namespace evidence and output I/O. The four actual historical captures and sub-100 ms local cost screen do not qualify a product change or a full-command speedup.
