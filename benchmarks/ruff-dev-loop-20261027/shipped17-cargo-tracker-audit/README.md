# Ohm 1.99.0-17 Cargo tracker audit

The released Linux Cargo identified itself as `a0c7d08c898d3fdff992f2f431dec57d2486add2`. We inspected all 18 open issues in the Ohm Cargo tracker on October 28 and exercised 13 reports with 37 actual release commands. All commands had an independent 35-second deadline. Two expected failed checks produced byte-identical diagnostics for an invalid Unicode environment value. Each other command exited successfully. [Cargo issue tracker](https://github.com/astral-sh/ohm-cargo/issues)

The public API hash, relink manifest, and relink recipe tests each installed a FIFO with no writer, edited the dependency, and printed 22. The Linux-only registry test generated an actual sparse registry and locked an inactive WASM crate whose package was unavailable. Linux fetch, offline build, and both offline checks succeeded. The legacy-null test deliberately substituted the predecessor’s JSON value in an actual non-Unicode environment fingerprint and retained the associated short-hash file. It tests the shipped decoder, with a synthetic legacy record rather than the original pair of historical debug builds.

Under the cache-corruption and workspace-isolation tests, the expected program ran, the three unrelated sibling files retained their original bytes, and cleaning one workspace preserved both the shared sentinel and the other workspace’s fingerprint. The eight-profile GC fixture removed the dependency bookkeeping after retiring all eight seeded payloads. The separate standalone PR for this repair was closed after its fix and regression went into the shipped #205 commit. [GC report](https://github.com/astral-sh/ohm-cargo/issues/225) · [Standalone PR](https://github.com/astral-sh/ohm-cargo/pull/226)

The remaining five issues were checked by commit ancestry. Three concern test fixtures. One concerns inheritance of the pruner’s file lock, and another concerns propagation of Ctrl-C through the optional early-test relay. `tracker.json` distinguishes the runtime runs from the ancestry checks. The audit covers these reported failure modes. Separate macro-cache tests found incorrect native output in this release after a legitimate tracked build-script update. No release-safety conclusion follows from these successful tracker regressions alone.

Run `python3 -IB verify.py` to reconstruct each command’s output and status. An optional `--cargo-git /path/to/ohm-cargo` also rechecks every recorded ancestor against the release commit. The generated registry, broken cache entries, symlink directory and clean targets all belonged to the experiment. The two workers store separate output roots.

An independent scan of all 124 stderr streams in three retained macro or foreign-source studies found zero `panicked at` or `internal compiler error` signatures across their released and experimental arms. The capsule records each transcript’s identity. Pass `--campaign-dir` with the directory containing those studies to recompute the scan. The scanner does not count failed fixture setup assertions as product failures.
