# Native procedural-macro expansions across incremental compilations

On shipped Ohm 1.99.0-17, a derive and an attribute can return values from an earlier version of a macro library. In the ordinary reproduction only a C function linked into the proc macro changes, from 17 to 29. The Rust file, macro crate metadata and dynamic symbol table stay identical. The first full compilation after the edit and a second full compilation both generated 17,17. An independent empty compilation generated 29,29. A second experiment made those macros generate ill-typed items. Both ordinary warm compiles exited successfully. The independent empty compiler reported two E0308 errors.

The private Rust change keeps the boolean flag syntax for compatibility. The parser leaves its tracked value disabled so the next full compilation uses the ordinary macro execution path. The checked-in test snapshots native code changes in both macro kinds. The existing compiler tests also check call-site warnings, panicking macro diagnostics, tracked environment and path observations, and mixed histories of source maps and hygiene.

## Native controls

Each synchronized Cargo run waited until the running compiler mapped the original macro library and returned an old token. The fixture then replaced the library with an equal-size file. The two files share all bytes of their Rust metadata and symbol tables. Their executable sections differ at the immediate value returned by the native function. Both replacement timestamps were tested, including the original nanosecond timestamp. The executing compile was expected to observe the old state. The next commands used the current library. The old compiler gave 17 for the cached derive and 29 for a freshly evaluated foreign-span join on two consecutive full compiles; an empty compile gave 29 for both.

Both compiler arms used a real Cargo build, an actual native build script and the same canonical Cargo build paths. A second upgrade starts from the physically installed -17 compiler. Its source, Cargo executable, flags, target and shared build directory are held fixed on the first post-upgrade command. The Rust documentation test compares the generated HTML declaration names under bare, last-yes and last-no boolean spellings. Released rustdoc ran both macros in all twelve source and option combinations and did not create an incremental directory.

## Reproduction

On a Linux Ohm toolchain, run `sh reproduce/run.sh`. It leaves an isolated temporary directory containing the two native builds and the reader. The release fails the edited warm-versus-empty assertion. The checked-in equivalent and the CI selection are in `private-rust.patch`.

Run `python3 verify.py` to reread all archived file hashes, compiler statuses, actual process arguments, ELF source identities, runtime outputs and decoded diagnostic spans. The intermediate compiler used rustc session normalization and is identified separately from the source-complete shared parser. The archives contain physical receipt files and executable digests. Native compiler libraries and complete target directories remain private. All commands are correctness controls.

The optimized R2 build used this PR’s exact `options.rs`. It also carried four changes from separate span/incremental work, listed in `final-subject.json`. Its two independently seeded ordinary Cargo projects both returned 29 on the first compiler switch and on the following fully fresh invocation. The same-source clean binaries matched the repaired direct caller builds. The first such compile already returned 29 for both macros with the exact clean executable bytes. All three checks on the #244 commit passed. The new C-linked regression targets Linux. The macOS job successfully ran its applicable compiler tests.

A separate ABI control ran two matched rustdoc installations on this fixture. Both generated the expected declarations.
